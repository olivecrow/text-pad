# 파일 처리 계약

이 문서는 파일 열기와 저장 흐름의 현재 기준만 다룬다.

## 현재 흐름

- 프론트엔드는 Tauri 대화상자 플러그인으로 사용자가 직접 선택한 경로만 받는다.
- 파일 읽기는 `read_file_content(path)` 명령으로 백엔드에 요청한다.
- 파일 저장은 `write_file_content(path, content)` 명령으로 백엔드에 요청한다.
- 편집 기준 데이터는 `fileContent` 원문 문자열이다.
- 새 파일 열기, 다른 파일 열기, 새 문서 만들기 전에 변경 사항이 있으면 사용자에게 확인한다.
- 앱을 닫기 전에 변경 사항이 있으면 저장, 저장 안 함, 취소 중 하나를 선택하게 한다.
- 닫기 전 저장을 선택했는데 아직 파일 경로가 없으면 저장 대화상자로 경로를 먼저 받는다. 사용자가 저장을 취소하거나 저장이 실패하면 닫기를 취소하고 편집 중인 원문을 유지한다.
- 파일을 열면 선택 영역과 스크롤 위치를 문서 처음으로 되돌린다.

## 확장자 범위

열기 대화상자는 다음 텍스트 계열 확장자를 허용한다.

- `txt`, `md`, `json`, `csv`, `tsv`, `yaml`, `yml`, `ini`, `cfg`, `log`, `js`, `ts`, `rs`, `html`, `css`

저장과 다른 이름으로 저장 대화상자는 현재 `txt`만 필터로 보여준다. 실제 저장 명령은 선택된 경로 문자열을 그대로 사용하므로, 저장 필터 확장은 프론트엔드 대화상자 설정을 먼저 맞추면 된다.

## 보존 기준

- 저장 시 사용자가 입력한 공백, 탭, 줄바꿈, 구분자를 임의로 정리하지 않는다.
- 렌더 모드에서 보이는 강조 색상이나 구조는 저장 내용에 반영하지 않는다.
- 읽기 실패, 저장 실패는 사용자에게 메시지로 알려야 하며, 편집 중인 원문은 유지한다.

## 남은 보강점

- 파일 인코딩 감지와 저장 시 보존.
- 줄바꿈 형식 감지와 저장 시 보존.
- 외부 프로그램이 같은 파일을 바꾼 경우의 충돌 감지.
- 큰 파일을 열 때 읽기 전용 모드나 확인 절차 제공.
