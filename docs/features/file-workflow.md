# 파일 처리 계약

이 문서는 파일 열기와 저장 흐름의 현재 기준만 다룬다.

## 현재 흐름

- 프론트엔드는 Tauri 대화상자 플러그인으로 사용자가 직접 선택한 경로를 받는다.
- 사용자가 JSON 파일 같은 텍스트 파일을 이 프로그램으로 직접 열면, 운영체제가 앱 실행 인자로 넘긴 파일 경로를 시작 파일로 읽는다.
- 파일 읽기는 `read_file_content(path)` 명령으로 백엔드에 요청한다.
- 시작 파일 경로 목록은 `get_startup_file_paths()` 명령으로 백엔드에 요청한다.
- 파일 저장은 `write_file_content(path, content)` 명령으로 백엔드에 요청한다.
- 저장 명령은 대상 파일을 직접 덮어쓰지 않고 같은 폴더의 임시 파일에 먼저 쓴 뒤 교체한다.
- 읽기와 저장 실패는 `code`와 `message`가 있는 파일 명령 오류로 전달한다.
- 편집 기준 데이터는 `fileContent` 원문 문자열이다.
- 파일은 탭 단위로 열린다. 깨끗한 빈 탭이 활성 상태이면 그 탭을 재사용하고, 그렇지 않으면 새 탭을 추가한다.
- 새 파일은 새 탭으로 추가한다.
- 각 탭은 파일 경로, 표시 이름, 원문, 변경 여부, 선택 영역, 스크롤 위치를 따로 가진다.
- 파일 경로가 없는 새 탭은 첫 줄의 공백을 제거한 값을 탭 제목으로 쓴다. 첫 줄이 비어 있으면 `제목 없음`으로 표시한다.
- 탭을 닫거나 앱을 닫기 전에 변경 사항이 있으면 저장, 저장 안 함, 취소 중 하나를 선택하게 한다.
- 닫기 전 저장을 선택했는데 아직 파일 경로가 없으면 저장 대화상자로 경로를 먼저 받는다. 사용자가 저장을 취소하거나 저장이 실패하면 닫기를 취소하고 편집 중인 원문을 유지한다.
- 파일 경로가 없는 새 탭을 저장할 때는 첫 줄 제목을 Windows 파일명으로 쓸 수 있게 정리한 값을 기본 파일명으로 제안한다.
- 파일을 열면 해당 탭의 선택 영역과 스크롤 위치를 문서 처음으로 둔다.
- 시작 파일이 있으면 메인 창을 표시하기 전에 깨끗한 빈 탭을 해당 파일 탭으로 바꾼다.

## 확장자 범위

열기 대화상자는 다음 텍스트 계열 확장자를 허용한다.

- `txt`, `md`, `json`, `csv`, `tsv`, `yaml`, `yml`, `ini`, `cfg`, `log`, `js`, `ts`, `rs`, `html`, `css`

저장과 다른 이름으로 저장 대화상자는 `txt`, `json`, 지원 텍스트 전체 필터를 보여준다. 실제 저장 명령은 선택된 경로 문자열을 그대로 사용한다.
파일 형식별 필터는 `src/lib/document-formats.ts`의 공통 목록을 기준으로 맞춘다.

## 보존 기준

- 저장 시 사용자가 입력한 공백, 탭, 줄바꿈, 구분자를 임의로 정리하지 않는다.
- 저장 도중 실패하더라도 기존 파일 손상 가능성을 줄이기 위해 임시 파일 기록과 교체 방식으로 저장한다.
- 원문 모드에서는 자동 쌍 문자 입력/삭제, Tab/Shift+Tab 들여쓰기, 들여쓰기 공백 백스페이스 삭제, 줄바꿈 시 들여쓰기 유지처럼 입력을 가로채 원문을 보정하는 편집 보조 기능을 적용하지 않는다.
- 렌더 모드의 편집 영역에서 탭 키는 코드 편집기처럼 들여쓰기로 동작한다. 탭 키는 공백 4개를 삽입하고, 여러 줄 선택 상태에서는 각 선택 줄 앞에 공백 4개를 붙인다. `Shift+Tab`은 각 선택 줄 앞의 공백 최대 4개나 탭 문자 1개를 제거한다. 줄 앞 들여쓰기 공백 안에서 백스페이스를 누르면 이전 4칸 경계까지 한 번에 제거한다.
- 렌더 모드의 줄바꿈 시 들여쓰기 유지 설정이 켜져 있으면 현재 줄의 선행 공백과 탭을 새 줄에 복사하고, 이렇게 생긴 빈 들여쓰기 줄에서는 백스페이스로 줄 전체를 지운다.
- 렌더 모드에서 보이는 강조 색상이나 구조는 저장 내용에 반영하지 않는다.
- 렌더 모드에서 데이터 파일 형식의 불리언 값 박스를 클릭하면 해당 원문 `true` 또는 `false`만 반대 값으로 바꾸고, 주변 공백과 구분자는 유지한다.
- `.json` 파일의 문법 오류 검사는 저장을 막지 않으며, 사용자가 입력한 오류가 있는 원문도 그대로 저장할 수 있다.
- 읽기 실패, 저장 실패는 파일 명령 오류의 `message`로 사용자에게 알려야 하며, 편집 중인 원문은 유지한다.

## 남은 보강점

- 파일 인코딩 감지와 저장 시 보존.
- 줄바꿈 형식 감지와 저장 시 보존.
- 외부 프로그램이 같은 파일을 바꾼 경우의 충돌 감지.
- 파일 대화상자 선택과 파일 읽기/쓰기 권한을 백엔드 경계에서 함께 추적.
- 큰 파일을 열 때 읽기 전용 모드나 확인 절차 제공.
