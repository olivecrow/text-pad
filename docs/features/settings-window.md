# 설정창 계약

설정창은 메인 편집기 안의 모달이 아니라 별도 Tauri 창이다.

## 창 구성

- `tauri.conf.json`에는 시작 성능을 위해 `main` 창만 정의하며, 메인 창은 편집기 준비 뒤 표시되도록 처음에는 숨김 상태로 둔다.
- `settings` 창은 앱 시작 때 만들지 않고, 설정 버튼을 처음 눌렀을 때 동적으로 만든다.
- 프론트엔드는 현재 창의 라벨이 `settings`인지 확인해 설정창 전용 화면을 렌더링한다.
- 설정창을 처음 열면 `일반` 화면을 표시한다. 표시 언어 드롭다운에는 시스템 기본값과 지원하는 10개 언어를 각 언어의 고유 이름으로 제공한다. 새 문서 기본 형식 드롭다운에는 제품이 지원하는 형식을 범주별로 제공하며 초기값은 Markdown이다.
- 사용자가 특정 표시 언어를 고르면 시스템 언어보다 우선하고, 시스템 기본값을 고르면 현재 시스템 언어를 다시 따른다.
- `일반` 화면에서 바꾼 새 문서 기본 형식은 이후에 만드는 새 탭부터 적용하고, 이미 열린 탭의 선택 형식은 바꾸지 않는다. CSV/TSV를 기본으로 고르면 새 탭은 변경되지 않은 빈 2행 2열 표로 시작한다.
- `설정 파일` 화면에서는 현재 설정 전체를 JSON 파일로 내보내고, 이전에 내보낸 JSON 설정 파일을 가져올 수 있다. 새 문서 기본 형식도 이 설정 파일에 포함하며, 작업 결과와 호환되지 않아 건너뛴 항목은 같은 화면의 상태 문구로 알린다.
- 창 상태 복원 플러그인은 메인 창만 대상으로 하며, `settings` 창은 복원 대상에서 제외한다.
- 왼쪽에는 검색창과 계층형 탐색 목록, 오른쪽에는 현재 경로·제목·설명과 설정 본문을 둔다. 본문과 탐색 목록은 독립적으로 스크롤하며, 하단에는 변경 사항이 즉시 적용된다는 안내를 유지한다.
- 탐색 목록은 `일반`, `편집기`, `파일 형식`, `설정 파일`로 나눈다. 편집기는 `원문 모드 → 글꼴 설정`, `렌더 모드 → 글꼴 설정 / 색상 / 편집`으로 구성한다. 글꼴 크기와 렌더 들여쓰기 변경은 같은 화면의 예시 문서에 반영한다.
- 렌더 모드 `편집` 화면의 자동 쌍 설정에는 캐럿 오른쪽이 어떤 문자열로 시작할 때 새 쌍을 허용할지 추가·제거하는 목록을 둔다. 공백은 제거할 수 없는 고정 예외이고, `=`와 `:`는 사용자가 제거할 수 있는 기본 예외 문자열이다.
- 파일 형식은 `문서`, `구조화 데이터`, `프로젝트 설정`, `표`, `자막 및 가사` 상위 카테고리 아래에 배치하며 처음에는 접어 둔다. 화살표는 펼침만 바꾸고, 범주 이름은 공통 설정 화면을 연다. 범주 화면의 형식 버튼을 누르면 해당 형식 설정으로 이동한다. 프로그래밍 언어 파일은 이 목록에 넣지 않는다. 하위 CSV나 JSON 같은 개별 형식에서는 그 형식의 렌더 표시와 렌더 편집을 설정한다.
- Markdown 형식 화면은 공통 렌더 표시·편집 토글 아래에 제목 표식 숨김, 1·2단계 제목 구분선, 제목 1~6단계별 크기 비율과 굵기 설정을 제공한다. 이 값은 한 Markdown 문서에만 붙지 않고 모든 `.md`와 `.markdown` 탭에 공통으로 적용한다.
- `표` 상위 카테고리에는 CSV와 TSV가 들어간다. 첫 행 강조, 행 번호 표시, 행·열 이동 애니메이션 사용 여부와 이동 시간처럼 두 형식에 공통인 설정은 이 화면에서 한 번만 다룬다.

렌더 모드 `색상` 화면은 편집 화면과 선택 영역, 구문과 기호, 문자 종류, 참과 거짓, 상태와 진단, 표 표시로 색상을 묶는다. 그룹을 펼쳐 세부 색상을 편집하고 예시 문서에서 대표 색상과 글꼴 굵기를 확인한다. 현재 앱 테마의 팔레트로 시작하며, 밝은·어두운 팔레트를 전환해도 앱의 표시 테마는 바꾸지 않는다. 기본 색상 복원은 선택한 팔레트에만 적용한다. 세부 연결과 파생 색상은 `theme-preferences.md`를 따른다.

## 검색과 키보드 탐색

- 검색은 현재 언어와 영어의 설정 이름·설명, 범주 경로, 파일 형식 이름과 확장자를 대상으로 한다. 여러 단어를 입력하면 모든 단어가 포함된 페이지를 찾는다.
- 검색 결과는 왼쪽 목록에 페이지와 경로를 표시한다. 결과를 선택하면 해당 페이지를 열고, 본문에서 일치하는 설정 행을 강조해 보이는 위치로 이동한다. 색상 검색 중에는 접힌 그룹도 펼쳐 숨은 항목을 찾을 수 있다.
- 결과가 없으면 왼쪽에 안내를 표시하고 현재 페이지와 설정값을 유지한다. 검색을 지워도 선택한 페이지를 유지하고 해당 파일 범주를 펼쳐 둔다.
- `Ctrl+F`는 설정 검색에 초점을 옮긴다. 검색창에서 `Enter`는 첫 결과를 열고, 아래 화살표는 목록으로 초점을 옮긴다. 목록에서는 위·아래 화살표와 `Home`·`End`로 이동하고 `Enter` 또는 `Space`로 선택한다. `Esc`는 검색어를 지우고 검색창에 초점을 둔다. 조합 입력 중에는 검색 단축키를 실행하지 않는다.
- 탐색 상태와 검색어, 팔레트 선택은 설정창 내부 상태이며 내보내는 설정 파일에 포함하지 않는다. 기존 설정 저장·창 간 동기화 계약은 유지한다.

## 열기와 닫기

설정 버튼 흐름은 다음 기준을 따른다.

1. `WebviewWindow.getByLabel("settings")`로 기존 설정창을 찾는다.
2. 앱 실행 후 첫 표시라면 메인 창의 현재 위치와 크기를 기준으로 설정창을 중앙에 둔다.
3. 있으면 `show()`로 표시하고 `setFocus()`로 초점을 옮긴다.
4. 없으면 라벨이 `settings`인 새 창을 만든다.
5. 설정창 닫기 요청은 창을 파괴하지 않고 `hide()`로 숨긴다.
6. 메인 창 종료 시에는 설정창을 `destroy()`로 정리한다.

사용자가 설정창을 직접 이동한 뒤에는 같은 앱 실행 세션에서 다시 열 때 위치를 강제로 되돌리지 않는다.

## 필요한 권한

접근 제어 목록은 프론트엔드가 호출할 수 있는 Tauri 기능을 제한하는 설정이다. 설정창 기능에는 최소한 다음 권한이 필요하다.

- `core:window:allow-show`
- `core:window:allow-set-focus`
- `core:window:allow-set-title`
- `core:window:allow-hide`
- `core:window:allow-set-position`
- `core:window:allow-destroy`
- `core:window:allow-close`
- `core:webview:allow-create-webview-window`
- `core:window:allow-create`
- `allow-open-file-dialog`
- `allow-save-file-dialog`

권한이 빠지면 설정 버튼을 눌렀을 때 `Command plugin:window|show not allowed by ACL` 같은 오류가 난다.
