# 편집기 실행 취소 계약

이 문서는 새 편집 기능을 추가할 때 앱 자체 실행 취소 시스템과 반드시 맞춰야 하는 기준이다.
사용자 관점의 전체 편집 행동과 기능별 실행 취소 경계는 `docs/features/natural-text-editing.md`와 `docs/features/natural-text-editing.en.md`를 우선 기준으로 하고, 이 문서는 기록 구조와 연결 방법을 구체화한다.

실행 취소는 사용자가 `Ctrl+Z`나 메뉴의 실행 취소를 눌렀을 때 이전 편집 상태로 돌아가는 기능이다. 다시 실행은 실행 취소한 편집을 다시 적용하는 기능이다. 이 앱은 브라우저 기본 실행 취소 기록을 쓰지 않고, 탭별 메모리 기반 자체 기록만 사용한다.

## 소유 경로

- `src/lib/editor-undo.ts`: 실행 취소 기록 전용 모듈이다. 원문 전체 복사 대신 변경 전후 공통 앞부분과 뒷부분을 제외한 실제 교체 범위, 변경 전 선택 영역, 변경 후 선택 영역을 저장한다.
- `src/routes/+page.svelte`: 편집 입력의 단일 진입 경로를 가진다. 모든 원문 변경은 현재 내용과 선택 영역의 변경 전후 상태를 만든 뒤 이 경로로 기록해야 한다.
- `commitEditorEdit`: 변경 전후 상태를 실행 취소 기록에 넣고 활성 탭의 원문과 선택 영역을 갱신하는 내부 함수다.
- `commitManualEditorEdit`: 메뉴, 단축키, 붙여넣기, 잘라내기, 시간 삽입, 렌더 토큰 클릭처럼 앱이 직접 계산한 편집 결과를 기록하는 내부 함수다.
- `commitRenderEditorEdit`: 렌더 모드 편집 보조 기능이 직접 계산한 편집 결과를 기록하는 내부 함수다.

새 파일이나 새 모듈에서 편집 기능을 분리하더라도 원문 변경은 위 함수와 같은 단일 기록 경로를 지나야 한다. 낮은 단계의 도우미 함수가 직접 `fileContent`, `textarea.selectionStart`, `textarea.selectionEnd`를 바꾸며 기록을 우회하면 안 된다.

## 기록 단위

실행 취소 한 번으로 되돌릴 범위는 사용자가 하나의 편집 동작으로 인식하는 전체 결과다.

- 일반 글자 입력과 반복 삭제는 같은 위치에서 짧게 이어질 때 하나의 실행 취소 단위로 합친다.
- 붙여넣기, 잘라내기, 메뉴 삭제, 시간과 날짜 삽입, 불리언 값 토글은 각각 하나의 실행 취소 단위다.
- CSV/TSV 셀의 짧게 이어지는 입력은 같은 셀 안에서 하나로 묶고, 행·열 추가·제거·이동은 각 조작 전체를 하나의 실행 취소 단위로 기록한다.
- 자동 쌍 문자 입력과 삭제, 백틱 코드 블록 확장, 글머리 형식 순환을 포함한 줄 들여쓰기 추가와 제거, 들여쓰기 공백 삭제, 글머리 기호 자동 이어쓰기, 줄바꿈 시 들여쓰기 유지, 빈 들여쓰기 줄 삭제, 화살표 기호 자동 변환은 각각 하나의 실행 취소 단위다.
- 색상 선택기는 선택기를 열 때의 값에서 최종 값까지 하나의 실행 취소 단위다. 선택 중간의 색상 변화는 화면에는 반영할 수 있지만 별도 기록으로 쌓지 않는다.
- 여러 단계로 원문을 고치는 새 편집 기능은 시작 전 상태와 최종 상태만 기록한다. 중간 단계는 사용자에게 보이더라도 실행 취소 기록으로 남기지 않는다.

커서 이동, 선택 영역 변경, 스크롤, 모드 전환, 설정 변경, 탭 전환처럼 원문을 바꾸지 않는 동작은 실행 취소 기록에 넣지 않는다.

## 새 편집 기능 추가 기준

새 편집 기능을 만들 때는 아래 순서를 따른다.

1. 이 기능이 원문 텍스트를 바꾸는지 먼저 판단한다. 원문을 바꾸지 않으면 실행 취소 기록을 만들지 않는다.
2. 원문을 바꾸면 변경 직전의 원문, 선택 시작 위치, 선택 끝 위치를 먼저 확보한다.
3. 기능 전체가 끝난 뒤의 원문, 선택 시작 위치, 선택 끝 위치를 계산한다.
4. 기능이 앱이 직접 계산한 편집이면 `commitManualEditorEdit`나 `commitRenderEditorEdit` 같은 명시적 기록 경로를 사용한다.
5. 기능이 브라우저 `textarea` 기본 입력을 통해 들어오는 일반 입력이면 `beforeinput`에서 변경 전 상태를 잡고 `input`에서 변경 후 상태를 기록하는 기존 경로를 유지한다.
6. 앱 전용 편집은 일반 입력 묶음을 끊고 독립 실행 취소 단위로 기록한다.
7. 실행 취소 뒤에는 원문뿐 아니라 선택 영역도 편집 전 상태로 돌아가야 한다. 다시 실행 뒤에는 편집 후 선택 영역으로 돌아가야 한다.

렌더 모드 전용 편집 기능은 상위 입력 경로에서 렌더 모드 여부를 판단하고, 실제 편집 계산 함수는 호출되면 자기 기능만 수행한다. 이 구조를 유지해야 원문 모드의 기본 입력 동작과 새 실행 취소 기록이 섞이지 않는다.

## 탭과 저장 기준

- 실행 취소 기록은 탭 식별자별 메모리에만 둔다.
- 새 탭, 파일 열기, 깨끗한 빈 탭을 열린 파일로 교체하는 흐름은 현재 원문을 기준으로 새 기록을 만든다.
- 탭을 닫으면 해당 탭의 실행 취소 기록도 삭제한다.
- 저장과 다른 이름 저장은 현재 실행 취소 위치를 저장 기준으로 표시한다.
- 변경 표시 여부는 현재 실행 취소 위치가 마지막 저장 위치와 같은지로 판단한다.

## 금지 사항

- `document.execCommand("undo")`나 `document.execCommand("redo")`를 다시 사용하지 않는다.
- 브라우저 기본 `historyUndo`, `historyRedo` 입력을 그대로 통과시키지 않는다.
- 새 편집 기능에서 `fileContent`만 직접 바꾸고 실행 취소 기록을 남기지 않는 경로를 만들지 않는다.
- 앱 전용 편집의 중간 상태를 여러 실행 취소 단계로 쌓지 않는다.

## 검증 기준

편집 기능을 추가하거나 수정하면 최소한 아래 동작을 확인한다.

- 새 편집 한 번이 실행 취소 한 번으로 모두 되돌아가는지 확인한다.
- 다시 실행이 같은 결과와 선택 영역을 복원하는지 확인한다.
- 일반 입력 묶음과 새 앱 전용 편집이 서로 잘못 합쳐지지 않는지 확인한다.
- 저장 뒤 실행 취소와 다시 실행에 따라 변경 표시가 맞게 바뀌는지 확인한다.
- 탭을 전환했다가 돌아와도 탭별 실행 취소 기록이 유지되는지 확인한다.
