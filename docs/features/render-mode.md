# 렌더 모드 계약

렌더 모드는 원문을 다시 작성하지 않고, 같은 텍스트를 읽기 쉽게 겹쳐 보여주는 표시 기능이다.
글머리, 자동 쌍 문자, 들여쓰기, 줄바꿈, 자동 변환, 캐럿과 선택 영역, 실행 취소를 함께 다루는 편집 행동은 `docs/features/natural-text-editing.md`와 `docs/features/natural-text-editing.en.md`를 우선 기준으로 한다.

## 표시 구조

- 실제 입력과 선택 범위는 여러 줄 텍스트 입력 요소인 HTML `textarea`가 담당한다. 렌더 레이어를 표시할 때 선택 배경은 `textarea`의 범위를 렌더 텍스트 노드에 옮겨 실제 글자 폭으로 그린다.
- 구문 강조, 줄 번호, 들여쓰기 가이드는 `textarea` 뒤의 배경 레이어가 담당한다.
- 두 레이어의 글꼴, 글자 크기, 줄 높이, 탭 크기, 스크롤 위치가 어긋나면 선택 영역과 글자가 맞지 않으므로 항상 함께 갱신한다.
- 선택 범위가 있는 동안에도 배경 레이어를 유지하고 렌더 텍스트의 반투명 선택 배경을 표시해 선택 중에도 구문 강조와 들여쓰기 표시가 유지되게 한다. 일반 글꼴과 고정폭 코드 글꼴이 섞인 줄에서도 선택 배경은 각 렌더 글자의 실제 너비에 맞춘다. 렌더 선택 표시를 지원하지 않는 환경이나 창 크기 변경으로 렌더 레이어가 잠시 숨겨진 동안에는 `textarea`의 기본 선택 배경을 사용한다.
- 렌더 모드에서 단순 클릭으로 캐럿을 옮기거나 커스텀 캐럿을 그릴 때 모든 줄에서 브라우저가 최종 배치한 렌더 텍스트 노드의 실제 DOM 범위를 사용한다. 글자 수나 평균 글자 폭으로 위치를 다시 추정하지 않으므로 한글·영문·고정폭 코드가 섞인 줄과 자동 줄바꿈 뒤에도 같은 원문 위치를 가리킨다. 줄 끝에서는 빈 렌더 노드를 제외하고 마지막 실제 글자의 오른쪽 경계에 캐럿을 표시한다. 기본 입력 캐럿은 숨기고 렌더 레이어 기준의 별도 캐럿을 표시하며, 캐럿 이동 직후에는 깜박임 주기를 처음부터 다시 시작한다. 드래그 선택처럼 선택 범위가 생긴 경우에는 이 보정을 적용하지 않는다.
- Windows CRLF 원문을 `textarea`에 넣으면 브라우저가 선택 위치를 LF 기준으로 계산하므로, 앱 상태와 편집 보조 기능은 `textarea` 선택 위치와 원문 위치를 서로 변환해서 사용한다.
- 앱 창 폭이 바뀌어 줄바꿈 레이아웃이 안정화되는 동안에는 오래된 배경 레이어와 줄번호를 그리지 않고 `textarea` 텍스트를 우선 표시한다.
- 렌더 모드는 저장 원문을 바꾸지 않고 앱 창 너비에 맞춰 표시 줄만 자동으로 접는다.

## 현재 강조 범위

- 파일 형식별 렌더 표시 설정이 켜진 형식만 아래 강조와 문법 검사를 적용한다.
- 한 쌍의 백틱으로 감싼 인라인 코드 조각.
- 세 개 이상의 백틱으로 감싼 여러 줄 코드 블록.
- 닫힘이 있는 작은따옴표와 큰따옴표 문자열.
- 단어에 붙어 줄임, 소유, 발음 표기 등에 쓰이는 작은따옴표 모양 기호는 문자열로 보지 않는다.
- 숫자.
- 줄 첫 공백 뒤의 숫자, 로마 숫자, 한 글자 영문자와 `.`, `)`, `()` 구분자로 이루어진 글머리 기호.
- 공백이나 줄 경계로 완전히 분리된 `#000000` 형태의 6자리 색상 코드.
- 파일 형식별 주석.
- 데이터 파일 형식의 불리언, 즉 참/거짓 값.
- `.json` 파일의 키, 문자열 값, 숫자, `true`, `false`, `null`, 콜론, 쉼표, 중괄호, 대괄호.
- `.json` 파일의 문법 오류 상태와 오류가 있는 줄 표시.
- `.jsonc`, `tsconfig.json`, `jsconfig.json`, `.vscode` 설정 파일의 JSON 구조, 줄·블록 주석, 후행 쉼표와 문법 오류 표시.
- `.jsonl`, `.ndjson` 파일의 줄별 JSON 값과 잘못된 줄 표시.
- `.xml`, `.xsd`, `.xsl`, `.xslt`, `.rss`, `.atom` 파일의 요소, 속성, 문자열, 엔터티, 처리 지시, CDATA와 well-formedness 오류 표시.
- `.po`, `.pot` 파일의 원문, 번역, 문맥, 참조, 플래그와 미번역 상태 표시.
- `.md`, `.markdown` 파일의 제목 단계, 링크, 굵은 강조, 기울임 강조, 인용 표식, 목록, 인라인·울타리 코드.
- `.toml`, `Cargo.lock`, `poetry.lock`, `.ini`, `.cfg`, `.conf`, `.properties`, `.env`, `.env.*`, `.gitconfig`, `.gitmodules`, `.editorconfig`, `.npmrc` 파일의 섹션, 키, 연산자, 값, 주석.
- `.gitignore`, `.gitattributes`, `.dockerignore`, 일반 ignore 파일, `.git/info/exclude`, `.git/info/sparse-checkout`, `.git/info/attributes`, `CODEOWNERS`의 경로 패턴, 와일드카드, 속성, 담당자와 반전 규칙.
- Git 커밋 메시지의 제목·트레일러·정리 주석, `.mailmap`의 신원·이메일, `.git-blame-ignore-revs`의 객체 ID.
- `.reg`, OpenSSH 설정, systemd 단위 파일, hosts 파일의 경로·섹션·지시어·값·IP·호스트 매핑.
- `.log` 파일의 시간과 TRACE/DEBUG/INFO/WARN/ERROR/FATAL 심각도.
- `.srt`, `.vtt`, `.lrc` 파일의 큐 번호, 시간, 메타데이터, 대사와 형식 오류 줄.
- `.yaml`, `.yml` 파일의 키, 값, 목록 표식, 주석, 문서 구분자, 블록 문자열 표식.
- `.yaml`, `.yml` 파일의 문법 오류 상태와 오류가 있는 줄 표시.
- 소괄호, 대괄호, 중괄호와 그 내부 중첩 구조.
- 괄호와 따옴표 같은 중첩 요소는 요소 종류보다 중첩 깊이를 우선해서 색상을 정한다.
- 들여쓰기 단계별 가이드 라인은 렌더 글꼴의 실제 공백 폭을 기준으로 각 들여쓰기 공백 위치에 맞춰 표시한다.

## 파일 형식별 주석

주석은 중앙 형식 등록부가 확장자, 관례적 파일명 또는 경로 패턴으로 판별한 형식의 문법만 인식한다. 프로그래밍 언어 파일은 지원 형식으로 판별하지 않는다.

- `.md`, `.markdown`: `<!-- ... -->`.
- XML: `<!-- ... -->`.
- `.jsonc`와 JSONC로 판별한 설정 파일: `//`, `/* ... */`.
- `.toml`, YAML, ENV, Gettext, Git·일반 ignore/attributes, Docker ignore, CODEOWNERS, OpenSSH, hosts: `#`.
- `.ini`, `.cfg`, `.conf`, Git config, EditorConfig, npmrc: 줄 첫 공백 뒤의 `;` 또는 `#`.
- systemd: 줄 첫 공백 뒤의 `#` 또는 `;`.
- REG: 줄 첫 공백 뒤의 `;`.
- `.properties`: 줄 첫 공백 뒤의 `#` 또는 `!`.

일반 소설, 로그, 표 데이터처럼 `.txt`, `.log`, `.csv`, `.tsv` 파일은 주석 강조 대상이 아니다.
`.json` 파일은 주석을 허용하지 않으며, 주석처럼 보이는 텍스트도 JSON 문법 오류로 검사한다.

## 파일 형식별 설정

- 설정창의 렌더 모드 트리 아래에서 각 파일 형식은 독립 메뉴로 표시된다. 각 형식 화면의 최상단에서 렌더 표시와 렌더 편집을 따로 켜고 끈다.
- 렌더 표시를 끄면 해당 형식의 강조, 주석 인식, JSON과 YAML 문법 검사 같은 형식별 렌더 모듈을 쓰지 않고 기본 텍스트 줄만 표시한다.
- 렌더 편집을 끄면 렌더 레이어에서 보이는 토큰을 클릭해 원문을 바꾸는 동작을 막는다.
- 렌더 편집은 렌더 표시가 켜져 있을 때만 의미가 있다. 렌더 표시가 꺼진 형식에서는 클릭 편집도 실행하지 않는다.
- 현재 설정 대상 형식은 중앙 등록부의 34개 형식이다. `텍스트`, `Markdown`, `Gettext`, `LOG`, `JSON`, `JSONC`, `JSON Lines`, `XML`, `YAML`, `TOML`, `INI/CFG`, `CONF`, `Properties`, `ENV`, `Windows 레지스트리`, `OpenSSH 설정`, `systemd`, `hosts`, Git·일반 ignore·프로젝트 설정, `CSV`, `TSV`, `SRT`, `WebVTT`, `LRC`를 포함한다. 프로그래밍 언어 파일은 설정 및 제품 지원 목록에서 제외한다.

## CSV/TSV 표 표시와 편집

- `.csv`와 `.tsv` 파일은 렌더 표시가 켜져 있을 때 줄 단위 강조 대신 표 편집기를 표시한다.
- CSV는 쉼표, TSV는 탭을 셀 구분자로 사용하며 인용된 구분자와 셀 내부 줄바꿈을 인식한다.
- 인용 셀이 닫히지 않았거나 인용 부호가 셀 중간에 잘못 나타나면 오류 행과 열을 표시한다. 오류가 있어도 원문 편집과 저장은 막지 않는다.
- 첫 번째 데이터 행 강조와 왼쪽 행 번호 표시는 도구 모음에서 각각 켜고 끈다.
- 렌더 편집이 켜져 있고 표가 2,000개 셀 이하이면 셀을 직접 편집하고 행·열을 추가, 제거, 드래그 이동할 수 있다. 한도를 넘으면 수만 개의 입력 요소를 만들지 않고 렌더 텍스트 표시로 전환한다.
- 원문 직렬화와 실행 취소 기준은 `docs/features/delimited-table.md`를 따른다.

## JSON 표시와 검사

- `.json` 파일은 저장 원문을 바꾸지 않고 렌더 레이어에서만 키, 값, 구분자, 중괄호, 대괄호를 구분해 표시한다.
- 확장자가 없는 새 탭은 내용의 첫 공백 아닌 글자가 `{` 또는 `[`이면 JSON 후보로 보고 같은 표시와 검사를 적용한다.
- 큰따옴표 문자열 뒤에 콜론이 오면 키로 표시한다.
- `true`와 `false`는 데이터 파일 형식 공통 불리언 값으로 표시하고, `null`은 JSON에서 정해진 빈 값으로 표시한다.
- 렌더 모드에서 불리언 값은 `true`를 연한 녹색 계열 박스로, `false`를 연한 붉은색 계열 박스로 표시한다.
- 렌더 모드에서 불리언 값 박스를 클릭하면 저장 원문에서 해당 값을 `true`와 `false` 사이로 토글한다.
- 불리언 값 박스 클릭은 기존 입력 커서와 선택 영역을 클릭한 값 쪽으로 옮기지 않는다.
- 키 색상은 깊이 기준으로 진한색, 중간색, 연한색 3단계를 반복해서 적용한다.
- JSON 문법 검사는 브라우저 내장 JSON 해석 함수인 `JSON.parse` 기준을 따른다.
- JSON 문법 검사는 입력마다 즉시 실행하지 않고, 사용자가 잠깐 입력을 멈춘 뒤 실행한다.
- 문법 오류가 있으면 상단 오류 표시와 상태 표시줄에 행과 열을 표시하고, 해당 줄의 줄 번호와 배경을 표시한다.
- 문법 오류가 있어도 원문 편집과 저장은 막지 않는다.
- JSON 렌더링은 기존 렌더 모드의 글꼴, 글자 크기, 탭 크기, 괄호 깊이 색상, 문자열 색상, 숫자 색상을 재사용한다.

## JSONC, TOML과 프로젝트 설정 표시

- `.jsonc`, `tsconfig.json`, `jsconfig.json`, `.vscode/settings.json`, `.vscode/tasks.json`, `.vscode/launch.json`은 JSONC로 판별한다. 키·값·괄호 표시와 불리언 클릭 편집은 JSON과 같고, 줄 주석과 블록 주석 및 후행 쉼표를 허용해 검사한다.
- `.toml`, `Cargo.lock`, `poetry.lock`은 TOML로 판별한다. 테이블과 테이블 배열, 키, 대입 연산자, 문자열, 숫자, 불리언, 주석을 구분하고 `smol-toml` 해석기를 기준으로 오류 행과 열을 표시한다.
- `.gitignore`, `.dockerignore`, `.git/info/exclude`, `.git/info/sparse-checkout`, 사용자 Git ignore 경로와 `.ignore`, `.npmignore`, `.prettierignore` 같은 일반 ignore 파일은 경로 부분과 `*`, `**`, `?`, 문자 범위, 디렉터리 구분자, 앞쪽 `!` 반전 규칙을 구분한다. 반전 규칙 줄에는 은은한 강조선을 표시한다.
- `.gitattributes`와 `.git/info/attributes`는 첫 열의 경로 패턴과 뒤쪽 속성, 속성 해제 `-`, 미지정 `!`, 값 대입 `=`을 구분한다.
- `.gitconfig`, `.gitmodules`, `.git/config`, `.git/config.worktree`, `.editorconfig`, `.npmrc`는 섹션, 키, 대입 연산자, 값, 주석을 구분한다. 섹션 줄에는 본문과 겹치지 않는 배경 강조를 표시한다.
- `CODEOWNERS`는 첫 열의 경로 패턴과 뒤쪽의 사용자·팀 담당자를 구분한다. 담당자는 밑줄과 전용 색으로 표시한다.
- `.gitmessage`, `COMMIT_EDITMSG`, `MERGE_MSG`, `TAG_EDITMSG`, `SQUASH_MSG`는 첫 유효 줄을 제목으로 강조하고 본문, `Signed-off-by` 같은 트레일러, 정리 주석과 가위 표식을 구분한다. 제목 길이 권고는 문법 오류로 취급하지 않는다.
- `.mailmap`은 대표 신원과 별칭 이메일을 구분하고, `.git-blame-ignore-revs`는 40자리 SHA-1 또는 64자리 SHA-256 객체 ID와 주석을 구분한다.
- 패턴 및 프로젝트 설정 형식의 진단은 빈 반전 규칙, 금지된 Git attributes 반전 패턴, 담당자 표기 누락, 닫히지 않은 섹션처럼 구현 간 차이 없이 명백한 오류만 보고한다.
- 모든 표시는 토큰 위치와 원문을 일대일로 유지한다. 렌더 편집 중에도 줄, 공백, 인용부호, 패턴, 속성, 담당자를 자동 정렬하거나 다시 쓰지 않는다.

## XML, Gettext와 운영체제 설정 표시

- XML은 요소 이름을 굵은 주색, 속성을 보조색, 값과 CDATA를 문자열색, 엔터티와 처리 지시를 표식색으로 구분한다. 원문이 바뀔 때만 전체 토큰을 다시 만들고, 같은 원문의 스크롤에서는 캐시에서 보이는 줄 범위만 선택한다. `fast-xml-parser`의 well-formedness 검사를 사용하며 DTD 스키마 유효성 검사는 수행하지 않는다.
- Gettext PO/POT는 `msgid` 원문에 파란 강조선, 번역된 `msgstr`에 녹색 강조선, 실제로 비어 있는 번역에 주황색 배경을 표시한다. 헤더 항목과 뒤에 문자열이 이어지는 여러 줄 `msgstr ""`은 미번역으로 표시하지 않는다.
- REG는 헤더, 레지스트리 키 경로, 값 이름, `dword:`·`hex:` 데이터 형식, 숫자 바이트, 삭제 표식과 여러 줄 연속 값을 구분한다. 앱은 REG를 레지스트리에 가져오지 않고 텍스트만 편집한다.
- OpenSSH 설정은 `Host`와 `Match` 범위를 섹션으로, 호스트 패턴과 지시어·값·주석을 구분한다. 새 OpenSSH 버전의 지시어를 막지 않도록 지시어 이름을 고정 목록으로 검사하지 않는다.
- systemd 단위 파일은 섹션, 지시어, 값, `%i` 같은 지정자, 환경 변수와 백슬래시 연속 줄을 구분한다. 빈 대입으로 값을 초기화하는 문법을 허용한다.
- hosts 파일은 IPv4·IPv6 주소, 하나 이상의 호스트 별칭과 인라인 주석을 구분한다. 명백히 잘못된 주소나 호스트 토큰만 오류로 표시한다.

## YAML 표시와 검사

- `.yaml`, `.yml` 파일은 저장 원문을 바꾸지 않고 렌더 레이어에서만 키, 값, 목록 표식, 주석, 문서 구분자를 구분해 표시한다.
- 확장자가 없는 새 탭은 내용의 첫 공백 아닌 부분이 `---` 또는 `%YAML`이면 YAML 후보로 보고 같은 표시와 검사를 적용한다.
- 콜론 뒤에 공백이나 줄 끝이 오는 위치를 키와 값의 구분자로 본다.
- `#`은 줄 시작이나 공백 뒤에 있고 따옴표 안에 있지 않을 때 주석으로 표시한다.
- `true`와 `false`는 데이터 파일 형식 공통 불리언 값으로 표시하고, 클릭하면 저장 원문의 해당 값만 반대로 바꾼다.
- `null`, `~`, 앵커, 별칭, 태그는 값 표식으로 표시한다.
- `|`, `>`, `|-`, `>+`처럼 블록 문자열을 시작하는 표식은 값 표식으로 표시하고, 이어지는 들여쓰기된 본문은 문자열 값으로 표시한다.
- YAML 문법 검사는 `yaml` 패키지의 여러 문서 파서를 기준으로 따른다.
- YAML 문법 검사는 입력마다 즉시 실행하지 않고, 사용자가 잠깐 입력을 멈춘 뒤 실행한다.
- 문법 오류가 있으면 상단 오류 표시와 상태 표시줄에 행과 열을 표시하고, 해당 줄의 줄 번호와 배경을 표시한다.
- 문법 오류가 있어도 원문 편집과 저장은 막지 않는다.
- YAML 렌더링은 기존 렌더 모드의 글꼴, 글자 크기, 탭 크기, 키 깊이 색상, 문자열 색상, 숫자 색상, 주석 색상을 재사용한다.

## Markdown 표시와 제목 편집

- 줄 첫 공백이 최대 세 칸인 위치의 `# `부터 `###### `까지를 제목 1~6단계로 인식한다. 울타리 코드 블록 안의 같은 텍스트는 제목으로 인식하지 않는다.
- 기본 설정에서는 제목의 `#`와 뒤 공백을 보이지 않게 하고, 원문 위치 계산을 위해 같은 폭의 숨은 구문으로 유지한다. 원문 문자열과 저장 결과는 바꾸지 않는다.
- 제목 본문은 단계별 크기 비율과 굵기를 적용한다. 기본값은 1단계 145%/700, 2단계 135%/700, 3단계 125%/600, 4단계 115%/600, 5단계 108%/600, 6단계 100%/600이다.
- 설정창에서 제목 표식 숨김, 1·2단계 구분선, 각 단계의 80~145% 크기와 400~800 굵기를 모든 Markdown 문서 공통으로 바꾼다.
- 링크, 굵은 강조, 기울임 강조, 인용 표식, 목록, 인라인 코드와 울타리 코드를 서로 다른 색·굵기·배경으로 구분한다.
- 제목 표식과 혼합 서식이 있는 줄의 클릭, 캐럿, 선택 영역은 렌더된 글자의 실제 폭을 기준으로 원문 위치에 대응한다.

## 줄 중심 형식 표시와 오류 검사

- JSON Lines는 빈 줄을 허용하고 빈 줄이 아닌 각 줄을 독립 JSON 문서로 검사한다. 첫 오류의 행과 열을 표시한다.
- INI/CFG, Properties, ENV는 확실한 섹션·할당 문법과 닫히지 않은 따옴표 또는 잘못된 유니코드 이스케이프를 검사한다. CONF는 구현마다 문법 차이가 커서 의미별 색 구분을 우선한다.
- LOG는 원문 순서를 바꾸지 않고 시간과 심각도를 강조한다.
- SRT는 큐 순서, 시작·종료 시간과 대사 존재를 검사하고, WebVTT는 헤더와 시간 줄을 검사하며, LRC는 줄 앞 시간·메타데이터 태그 형식을 검사한다.
- 형식 오류는 편집과 저장을 막지 않는다. 오류 줄을 고친 뒤 잠시 입력을 멈추면 표시가 사라진다.

## 파싱 기준

- 줄 단위 토큰화를 사용한다.
- 글머리 기호는 줄 첫 공백 뒤에 있고 구분자와 공백이 뒤따르는 `1. `, `II. `, `A. `, `1) `, `a) `, `(1) `, `(a) ` 같은 순서 있는 표식과 `- `, `* `, `+ `, `• ` 순서 없는 표식을 강조한다.
- 렌더 모드에서 인식한 글머리 줄은 표식 칸과 본문 칸을 분리한 두 열 격자로 배치한다. 본문 칸은 독립된 줄바꿈 폭을 가지므로 첫 줄과 자동 줄바꿈 표시 줄이 같은 왼쪽 경계를 사용한다. `Shift+Enter` 연속 줄의 선행 공백은 원문 호환용 구조로 유지하되 렌더 본문 칸의 편집 가능한 공백으로 취급하지 않는다.
- 접힌 캐럿과 클릭 위치는 글머리 표식 칸 및 연속 줄의 구조 영역을 건너뛴다. 연속 줄 본문 시작의 `ArrowLeft`는 윗줄 끝으로 이동하고, 그 위치의 `Backspace`는 줄바꿈과 구조 영역을 함께 제거해 윗줄과 합친다. 글머리 첫 줄 본문 시작의 `Backspace`는 마침표 같은 표식의 마지막 보이는 문자와 뒤 구조 간격을 함께 제거해 글머리 적용을 끝낸다.
- 괄호와 따옴표처럼 안쪽 구조가 필요한 요소는 트리 형태 토큰으로 만든다.
- 공백이나 줄 경계로 완전히 분리된 `#000000` 형태의 색상 코드는 `#` 주석보다 먼저 판정한다.
- 주석 안에 들어 있는 `#000000` 형태의 색상 코드도 공백이나 줄 경계로 완전히 분리된 경우에만 주석보다 안쪽 요소로 다시 강조한다.
- 색상 코드의 배경과 테두리는 실제 글자 폭을 바꾸지 않는 방식으로 표시해 원문 입력 커서 위치와 렌더 표시 위치를 맞춘다.
- 색상 코드 안에 입력 커서가 있을 때는 색상 코드 배경과 대비되는 입력 커서 색을 사용한다.
- 렌더 레이어는 화면에 보이는 줄과 그 주변 줄만 렌더 토큰으로 만든다.
- 자동 줄바꿈은 공백 기준 단어 단위 줄바꿈을 우선하고, 창 너비보다 긴 단일 단어만 표시 폭을 넘기지 않도록 내부에서 접는다.
- 자동 줄바꿈으로 생긴 표시 줄은 원문에 줄바꿈 문자를 추가하지 않으며, 줄 번호는 원문 줄 하나에 하나만 표시한다.
- 화면에 표시된 원문 줄의 높이는 브라우저의 최종 줄바꿈 결과를 실측하고, 다음 원문 줄과 줄 번호는 그 실측 높이 뒤에 배치해 서로 겹치지 않게 한다.
- 색상 코드에 마우스를 올리면 입력 영역 커서를 조작 가능 상태로 바꾼다.
- 색상 코드를 클릭하면 별도 정사각형 색상 필드를 만들지 않고, 숨겨진 앵커를 통해 운영체제 색상 선택기만 연다.
- 색상 선택기의 숨겨진 앵커는 색상 코드의 오른쪽 끝을 기준으로 배치하고, 화면 여백에 따라 위치를 보정한다.
- 색상 선택기의 숨겨진 앵커는 화면에 보이는 픽셀을 남기지 않아야 하며, 색상 코드가 없어지거나 선택기 적용이 끝나면 편집 영역 밖으로 치운다.
- 불리언 값 박스는 좌우 안쪽 여백을 넣되, 같은 크기의 좌우 바깥 여백 보정으로 주변 토큰 위치가 밀리지 않게 한다.
- 자동 쌍 문자 편집 설정이 켜져 있으면 렌더 모드에서 캐럿만 놓인 상태로 여는 괄호나 따옴표를 입력할 때 닫는 짝 문자를 함께 넣고 캐럿을 가운데로 둔다. 캐럿 오른쪽에 입력한 닫는 괄호, 따옴표, 백틱과 같은 문자가 이미 있으면 원문을 바꾸지 않고 캐럿만 그 문자 뒤로 옮긴다.
- 줄 시작의 들여쓰기 뒤에서 백틱을 세 번 연속 입력하면 세 번째 입력에서 여는 백틱 세 개, 빈 코드 줄, 닫는 백틱 세 개와 그 뒤의 같은 들여쓰기 줄로 확장하고 캐럿은 빈 코드 줄 안에 둔다. 닫는 울타리 직후의 접힌 캐럿 위치는 숨은 백틱 줄이 아니라 그 다음 줄의 첫 편집 위치를 가리킨다. 기존 줄바꿈 형식과 들여쓰기를 유지하며, 전체 확장을 하나의 실행 취소 단위로 기록한다.
- 숨긴 인라인 백틱과 코드 블록 울타리는 접힌 캐럿 위치로 사용하지 않는다. 클릭과 방향키는 보이는 코드 경계 또는 코드 블록 안팎의 인접한 편집 줄로 건너뛴다. 닫는 울타리 바로 다음 줄의 선행 공백 안에서 `Backspace`를 누르면 코드 내용과 줄은 유지하고 여닫는 울타리의 연속 백틱을 각각 두 개로 줄여 코드 블록 문법만 해제하며, 캐럿은 닫는 울타리에 남은 두 백틱 바로 뒤의 제거 위치로 옮긴다. 코드 블록 전체 선택 삭제도 허용한다.
- 자동 쌍 문자 편집 설정이 켜져 있으면 렌더 모드에서 자동 쌍 문자 사이에 캐럿만 있고 안쪽 내용이 비어 있을 때 앞 글자를 지우면 닫는 짝 문자도 함께 지운다. 단, `"""`나 `(()`처럼 바깥 닫힘이 없어 가운데 글자만 감싸진 상태에서는 가운데 글자만 지운다.
- 렌더 모드에서 `Tab`과 `Shift+Tab`은 캐럿 위치에 공백을 넣지 않고 캐럿이 있는 줄 또는 선택한 모든 줄 전체의 들여쓰기를 추가하고 제거한다. 글머리 기호가 있는 줄은 목표 들여쓰기 깊이에 맞춰 글머리 형식도 함께 바꾼다. 줄 앞 들여쓰기 공백 안에서 `Backspace`를 누르면 이전 4칸 경계까지 공백을 한 번에 지운다. 내용이 없는 줄에서도 `Tab`으로 들여쓴 뒤 그 위치부터 텍스트를 입력할 수 있다.
- 순서 있는 글머리 형식은 깊이 0부터 `I. `, `A. `, `1. `, `i. `, `a. `, `1) `, `a) `, `(1) `, `(a) ` 순서로 적용한다. 더 깊어지면 숫자와 소문자를 짝으로 두고 구분자 `.`, `)`, `()` 순서를 반복한다. 순서 없는 글머리는 이 계열과 섞지 않고 깊이마다 `- `, `* `, `+ `, `• ` 순으로 순환한다.
- 화살표 기호 자동 변환 설정이 켜져 있으면 렌더 모드에서 `-->`, `<--`, `<->`, `==>`, `<==`, `<=>`를 공백이나 문서 시작 뒤에 단독으로 입력한 다음 스페이스를 누를 때 각각 `→`, `←`, `↔`, `⇒`, `⇐`, `⇔`로 바꾸고 뒤에 공백을 남긴다.
- 렌더 모드에서 글머리 기호가 있는 줄의 표식 뒤에서 `Enter`를 누르면 현재 글머리 종류와 구분자를 유지해 다음 항목을 만든다. 순서 있는 표식은 다음 순번을 사용하고, 순서 없는 표식은 현재 기호를 그대로 이어 쓴다. 캐럿 뒤의 텍스트는 새 표식 뒤로 이동하고, 같은 들여쓰기와 표식 뒤 공백을 유지한다. 같은 깊이와 구분자의 연속된 순서 있는 뒤 항목은 순번을 하나씩 증가시키며, 더 깊은 하위 줄은 건너뛰되 빈 줄이나 같은 깊이의 다른 문맥에서 자동 순서 범위를 끝낸다.
- 현재 줄이 선행 들여쓰기와 글머리 표식만으로 이루어진 빈 항목이면 일반 `Enter`는 새 줄이나 다음 표식을 만들지 않고 현재 표식만 제거해 목록을 끝낸다. 중첩 항목의 선행 들여쓰기는 유지하고, 뒤 항목의 순번은 바꾸지 않는다.
- 같은 위치에서 `Shift+Enter`를 누르면 새 글머리 없이 현재 렌더 글꼴로 측정한 본문 시작 폭의 가장 가까운 공백 경계에 맞춰 들여쓴 연속 줄을 만들고, 뒤 항목의 순번은 유지한다.
- 이 연속 줄에서 보조 키 없이 `Enter`를 누르면 빈 줄이나 더 얕은 일반 문단을 넘지 않는 소유 글머리의 다음 항목을 만들고, 연속된 뒤 항목의 순번도 맞춘다. 소유 글머리를 찾지 못하면 일반 들여쓰기 유지로 처리한다.
- 줄바꿈 시 들여쓰기 유지 설정이 켜져 있으면 렌더 모드에서 `Enter`를 누를 때 현재 줄의 선행 공백과 탭을 다음 줄에 복사한다.
- 줄바꿈 시 들여쓰기로 생긴 빈 줄에서 `Backspace`를 누르면 같은 들여쓰기 문자열을 가진 윗줄과 합치고 캐럿을 윗줄 끝으로 옮긴다. 이 동작은 일반 들여쓰기 한 단위 삭제보다 먼저 적용한다.
- 자동 쌍 문자 입력과 삭제, 백틱 코드 블록 확장과 울타리 문법 해제, 글머리 형식 순환을 포함한 줄 들여쓰기 추가와 제거, 들여쓰기 공백 삭제, 뒤 항목의 자동 순서 변경을 포함한 글머리 기호 자동 이어쓰기, 빈 글머리 항목의 일반 `Enter` 목록 종료, 글머리 없는 `Shift+Enter` 연속 줄과 그 연속 줄의 일반 `Enter` 다음 항목 생성, 줄바꿈 시 들여쓰기 유지, 빈 들여쓰기 줄 삭제, 화살표 기호 자동 변환은 각각 하나의 실행 취소 단위로 기록한다.
- 색상 코드 선택기는 선택기를 열 때의 값에서 최종 값까지 하나의 실행 취소 단위로 기록한다. 선택 중 발생하는 중간 색상 변화는 화면에만 반영하고 별도 실행 취소 단계로 쌓지 않는다.
- 데이터 파일 형식의 불리언 값 클릭 편집은 한 번의 토글을 하나의 실행 취소 단위로 기록한다.
- 여러 줄 주석은 닫힘이 나올 때까지 다음 줄 상태를 이어 간다.
- JSON 문자열은 같은 줄 안에서 닫힘이 확인된 경우 문자열 또는 키로 표시하고, 닫힘이 없으면 오류 토큰으로 표시한다.
- JSON 키 깊이는 현재 괄호와 대괄호 중첩 수를 기준으로 계산하며, 가장 바깥 객체의 키를 1단계로 본다.
- YAML 키 깊이는 들여쓰기 깊이를 기준으로 계산하며, 가장 바깥 키를 1단계로 본다.
- YAML 블록 문자열 본문은 다음 줄의 들여쓰기가 블록 문자열 시작 줄보다 깊은 동안 문자열 값으로 표시한다.
- 괄호와 따옴표는 같은 줄 안에서 닫힘이 확인된 경우에만 강조하고, 닫힘이 없으면 일반 텍스트로 둔다.
- 인라인 코드와 백틱 코드 블록의 울타리 및 내부 문자는 렌더 모드 글꼴 설정과 관계없이 고정폭 글꼴 목록으로 표시하되 본문과 같은 글자 크기와 줄 높이를 사용한다. 인라인 코드는 양쪽 백틱 사이에 공백이 아닌 내용이 있을 때만 백틱을 숨기고, 내용이 없거나 공백뿐이면 백틱을 보여 빈 코드 영역임을 알 수 있게 한다. 여러 줄 코드 블록의 여닫는 울타리 줄은 원문 좌표 계산을 위한 자리를 유지한 채 보이지 않게 하고, 접힌 캐럿은 숨은 구문 안에 머물지 않게 한다. 코드 블록 채우기는 숨긴 울타리 줄에서 위아래 약 12px만 사용하고 편집 영역 좌우에서 약 12px 안쪽에 배치하며, 배경 안에서도 코드 텍스트와 좌우 가장자리 사이에 약 12px의 안쪽 여백을 유지한다. 인라인 코드는 글자 범위만 배경색으로 강조하고, 여러 줄 코드 블록은 여는 울타리부터 닫는 울타리까지 연속된 하나의 채우기 배경으로 묶되 별도 아웃라인은 그리지 않는다. 코드 텍스트와 선택 강조는 채우기 위에 표시한다. 코드 기본 글자색은 내부 괄호, 글머리 기호, 문자열, 숫자 등 다른 구문 색상보다 낮은 우선순위로 적용하고 다크 테마 기본값은 채도를 낮춘다. 코드 배경색과 기본 글자 색상은 라이트·다크 테마별 색상 설정에서 변경할 수 있다.
- 닫힘이 확인된 중첩 요소는 최종 토큰 트리의 바깥쪽에서 안쪽 순서대로 깊이를 다시 계산한다.
- 깊이 색상은 기존 렌더 색상 설정을 재사용하며, 깊이가 색상 우선순위가 된다.
- 키 색상은 키 전용 깊이 색상을 우선 적용하며, 일반 괄호 깊이 색상으로 덮어쓰지 않는다.
- Svelte 템플릿 공백이 실제 글자 폭에 영향을 주지 않도록 토큰 재귀 렌더링 부분은 불필요한 줄바꿈과 공백을 넣지 않는다.
- 강조 색상은 CSS 변수로 주입하고 저장 원문에는 영향을 주지 않는다.

## 성능 기준

- 화면에 보이는 줄 주변만 렌더링하는 가상화 표시를 유지한다. XML처럼 문서 전체 문맥이 필요한 토큰은 원문 버전별로 한 번만 만들고, 스크롤할 때는 이진 탐색으로 화면 범위와 겹치는 토큰만 줄 렌더러에 전달한다.
- 원문 모드와 향상 렌더 한도를 넘은 대체 표시는 균일 줄 높이만 사용하며, 문서 줄 수만큼 위쪽 위치·높이·목록 배열을 만들지 않는다.
- 자동 줄바꿈 렌더 레이아웃은 줄 높이 누적 인덱스를 유지한다. 같은 줄 수의 국소 편집은 변경 줄부터 목록 소유자와 추정 높이가 기존 상태와 다시 같아지는 지점까지만 계산하고, 줄 추가·삭제는 변경 줄 뒤쪽만 다시 만든다.
- 울타리 코드 범위는 편집 지점이 속한 울타리의 여는 줄 또는 편집 줄부터 다시 찾고, 그 앞에서 닫힌 범위는 재사용한다.
- Markdown 여러 줄 주석, 일반 여러 줄 주석, JSONC 블록 주석, YAML 블록 문자열의 시작 상태는 256줄 간격 체크포인트로 저장한다. 깊은 위치를 스크롤할 때 문서 첫 줄부터 다시 토큰화하지 않는다.
- JSON, JSONC, JSON Lines, XML, YAML, TOML과 지원 설정 형식의 문법 검사는 500ms 입력 대기 뒤 웹 작업자 스레드에서 실행한다. 새 입력이나 형식 변경이 생기면 이전 작업자를 종료하고 최신 요청 결과만 반영한다. 작업자를 만들 수 없거나 실행에 실패한 환경에서는 같은 검사를 UI 스레드에서 실행해 결과 계약을 유지한다.
- 입력 이벤트가 계산한 교체 범위와 새 CRLF 위치 인덱스는 실행 취소와 렌더 캐시가 함께 사용해 같은 원문 비교를 반복하지 않는다.
- 텍스트 폭 캐시는 최근 사용 순서로 최대 12,000개 항목만 유지하고, 창 간 탭 수신 식별자는 최근 256개만 유지한다.
- 긴 한 줄의 클릭 위치는 브라우저 기본 좌표 변환이나 DOM 범위 이진 탐색으로 찾으며, 글자 수만큼 범위 객체를 만들지 않는다.
- CRLF와 LF 위치 변환은 원문 버전별 인덱스를 공유하고 입력 이벤트마다 전체 앞부분을 다시 순회하지 않는다.
- 큰 파일에서도 전체 줄을 DOM 요소로 한꺼번에 만들지 않는다.
- 창 폭 변경 중에는 보이지 않는 렌더 배경과 줄번호 갱신을 건너뛰고, 안정화된 뒤 보이는 줄 범위만 다시 렌더링한다.
- 수직 스크롤은 원문 `textarea` 기준으로 동기화한다.
- 렌더 모드는 자동 줄바꿈을 기준으로 표시하므로 일반 텍스트에서는 수평 스크롤을 만들지 않는다.

## Windows 가로 휠

Windows WebView2가 일부 가로 휠 입력을 브라우저 이벤트로 제대로 넘기지 않기 때문에, 백엔드가 `WM_MOUSEHWHEEL` 메시지를 받아 `native-horizontal-wheel` 이벤트로 전달한다. 프론트엔드는 원문 모드처럼 가로 스크롤이 있는 표시 상태에서 이 값을 받아 `textarea`의 가로 스크롤 위치에 반영한다.
