# 렌더 모드 계약

렌더 모드는 원문을 다시 작성하지 않고, 같은 텍스트를 읽기 쉽게 겹쳐 보여주는 표시 기능이다.

## 표시 구조

- 실제 입력과 선택 영역은 여러 줄 텍스트 입력 요소인 HTML `textarea`가 담당한다.
- 구문 강조, 줄 번호, 들여쓰기 가이드는 `textarea` 뒤의 배경 레이어가 담당한다.
- 두 레이어의 글꼴, 글자 크기, 줄 높이, 탭 크기, 스크롤 위치가 어긋나면 선택 영역과 글자가 맞지 않으므로 항상 함께 갱신한다.
- 선택 범위가 있는 동안에도 배경 레이어를 유지하고 `textarea`의 반투명 선택 배경만 겹쳐 표시해 선택 중에도 구문 강조와 들여쓰기 표시가 유지되게 한다.
- 앱 창 폭이 바뀌어 줄바꿈 레이아웃이 안정화되는 동안에는 오래된 배경 레이어와 줄번호를 그리지 않고 `textarea` 텍스트를 우선 표시한다.
- 렌더 모드는 저장 원문을 바꾸지 않고 앱 창 너비에 맞춰 표시 줄만 자동으로 접는다.

## 현재 강조 범위

- 파일 형식별 렌더 표시 설정이 켜진 형식만 아래 강조와 문법 검사를 적용한다.
- 백틱 코드 조각.
- 닫힘이 있는 작은따옴표와 큰따옴표 문자열.
- 단어에 붙어 줄임, 소유, 발음 표기 등에 쓰이는 작은따옴표 모양 기호는 문자열로 보지 않는다.
- 숫자.
- 줄 첫 공백 뒤의 숫자, 로마 숫자, 한 글자 영문자 글머리 기호.
- 공백이나 줄 경계로 완전히 분리된 `#000000` 형태의 6자리 색상 코드.
- 파일 형식별 주석.
- 데이터 파일 형식의 불리언, 즉 참/거짓 값.
- `.json` 파일의 키, 문자열 값, 숫자, `true`, `false`, `null`, 콜론, 쉼표, 중괄호, 대괄호.
- `.json` 파일의 문법 오류 상태와 오류가 있는 줄 표시.
- `.yaml`, `.yml` 파일의 키, 값, 목록 표식, 주석, 문서 구분자, 블록 문자열 표식.
- `.yaml`, `.yml` 파일의 문법 오류 상태와 오류가 있는 줄 표시.
- 소괄호, 대괄호, 중괄호와 그 내부 중첩 구조.
- 괄호와 따옴표 같은 중첩 요소는 요소 종류보다 중첩 깊이를 우선해서 색상을 정한다.
- 들여쓰기 단계별 가이드 라인.

## 파일 형식별 주석

주석은 파일 이름의 마지막 점 뒤 문자열인 확장자에 맞는 문법만 인식한다. 확장자가 없거나 아래 목록에 없으면 주석 강조를 하지 않는다.

- `.bash`, `.py`, `.r`, `.rb`, `.sh`, `.toml`, `.yaml`, `.yml`, `.zsh`: `#`.
- `.c`, `.cpp`, `.cs`, `.go`, `.h`, `.java`, `.js`, `.jsx`, `.kt`, `.rs`, `.swift`, `.ts`, `.tsx`: `//`, `/* ... */`.
- `.php`: `//`, `#`, `/* ... */`.
- `.css`: `/* ... */`.
- `.html`, `.md`, `.svg`, `.xml`: `<!-- ... -->`.
- `.ini`, `.cfg`: 줄 첫 공백 뒤의 `;` 또는 `#`.
- `.bat`, `.cmd`: 줄 첫 공백 뒤의 `REM` 또는 `::`.
- `.ps1`: `#`, `<# ... #>`.
- `.sql`: `--`, `/* ... */`.
- `.lua`: `--`, `--[[ ... ]]`.
- `.vim`: `"`.
- `.jsonc`: `//`, `/* ... */`.

일반 소설, 로그, 표 데이터처럼 `.txt`, `.log`, `.csv`, `.tsv` 파일은 주석 강조 대상이 아니다.
`.json` 파일은 주석을 허용하지 않으며, 주석처럼 보이는 텍스트도 JSON 문법 오류로 검사한다.

## 파일 형식별 설정

- 설정창의 렌더 모드 트리 아래에서 각 파일 형식은 독립 메뉴로 표시된다. 각 형식 화면의 최상단에서 렌더 표시와 렌더 편집을 따로 켜고 끈다.
- 렌더 표시를 끄면 해당 형식의 강조, 주석 인식, JSON과 YAML 문법 검사 같은 형식별 렌더 모듈을 쓰지 않고 기본 텍스트 줄만 표시한다.
- 렌더 편집을 끄면 렌더 레이어에서 보이는 토큰을 클릭해 원문을 바꾸는 동작을 막는다.
- 렌더 편집은 렌더 표시가 켜져 있을 때만 의미가 있다. 렌더 표시가 꺼진 형식에서는 클릭 편집도 실행하지 않는다.
- 현재 설정 대상 형식은 `텍스트`, `Markdown`, `JSON`, `CSV`, `TSV`, `YAML`, `INI/CFG`, `LOG`, `JavaScript`, `TypeScript`, `Rust`, `HTML`, `CSS`다.

## JSON 표시와 검사

- `.json` 파일은 저장 원문을 바꾸지 않고 렌더 레이어에서만 키, 값, 구분자, 중괄호, 대괄호를 구분해 표시한다.
- 확장자가 없는 새 탭은 내용의 첫 공백 아닌 글자가 `{` 또는 `[`이면 JSON 후보로 보고 같은 표시와 검사를 적용한다.
- 큰따옴표 문자열 뒤에 콜론이 오면 키로 표시한다.
- `true`와 `false`는 데이터 파일 형식 공통 불리언 값으로 표시하고, `null`은 JSON에서 정해진 빈 값으로 표시한다.
- 렌더 모드에서 불리언 값은 `true`를 연한 녹색 계열 박스로, `false`를 연한 붉은색 계열 박스로 표시한다.
- 렌더 모드에서 불리언 값 박스를 클릭하면 저장 원문에서 해당 값을 `true`와 `false` 사이로 토글한다.
- 불리언 값 박스 클릭은 기존 입력 커서와 선택 영역을 클릭한 값 쪽으로 옮기지 않는다.
- 키 색상은 깊이 기준으로 진한색, 중간색, 연한색 3단계를 반복해서 적용한다.
- JSON 문법 검사는 브라우저 내장 JSON 해석 함수인 `JSON.parse` 기준을 따른다.
- JSON 문법 검사는 입력마다 즉시 실행하지 않고, 사용자가 잠깐 입력을 멈춘 뒤 실행한다.
- 문법 오류가 있으면 상단 오류 표시와 상태 표시줄에 행과 열을 표시하고, 해당 줄의 줄 번호와 배경을 표시한다.
- 문법 오류가 있어도 원문 편집과 저장은 막지 않는다.
- JSON 렌더링은 기존 렌더 모드의 글꼴, 글자 크기, 탭 크기, 괄호 깊이 색상, 문자열 색상, 숫자 색상을 재사용한다.

## YAML 표시와 검사

- `.yaml`, `.yml` 파일은 저장 원문을 바꾸지 않고 렌더 레이어에서만 키, 값, 목록 표식, 주석, 문서 구분자를 구분해 표시한다.
- 확장자가 없는 새 탭은 내용의 첫 공백 아닌 부분이 `---` 또는 `%YAML`이면 YAML 후보로 보고 같은 표시와 검사를 적용한다.
- 콜론 뒤에 공백이나 줄 끝이 오는 위치를 키와 값의 구분자로 본다.
- `#`은 줄 시작이나 공백 뒤에 있고 따옴표 안에 있지 않을 때 주석으로 표시한다.
- `true`와 `false`는 데이터 파일 형식 공통 불리언 값으로 표시하고, 클릭하면 저장 원문의 해당 값만 반대로 바꾼다.
- `null`, `~`, 앵커, 별칭, 태그는 값 표식으로 표시한다.
- `|`, `>`, `|-`, `>+`처럼 블록 문자열을 시작하는 표식은 값 표식으로 표시하고, 이어지는 들여쓰기된 본문은 문자열 값으로 표시한다.
- YAML 문법 검사는 `yaml` 패키지의 여러 문서 파서를 기준으로 따른다.
- YAML 문법 검사는 입력마다 즉시 실행하지 않고, 사용자가 잠깐 입력을 멈춘 뒤 실행한다.
- 문법 오류가 있으면 상단 오류 표시와 상태 표시줄에 행과 열을 표시하고, 해당 줄의 줄 번호와 배경을 표시한다.
- 문법 오류가 있어도 원문 편집과 저장은 막지 않는다.
- YAML 렌더링은 기존 렌더 모드의 글꼴, 글자 크기, 탭 크기, 키 깊이 색상, 문자열 색상, 숫자 색상, 주석 색상을 재사용한다.

## 파싱 기준

- 줄 단위 토큰화를 사용한다.
- 글머리 기호는 줄 첫 공백 뒤에 있고 마침표와 공백이 뒤따르는 `1. `, `II. `, `A. ` 같은 표식만 강조한다.
- 괄호와 따옴표처럼 안쪽 구조가 필요한 요소는 트리 형태 토큰으로 만든다.
- 공백이나 줄 경계로 완전히 분리된 `#000000` 형태의 색상 코드는 `#` 주석보다 먼저 판정한다.
- 주석 안에 들어 있는 `#000000` 형태의 색상 코드도 공백이나 줄 경계로 완전히 분리된 경우에만 주석보다 안쪽 요소로 다시 강조한다.
- 색상 코드의 배경과 테두리는 실제 글자 폭을 바꾸지 않는 방식으로 표시해 원문 입력 커서 위치와 렌더 표시 위치를 맞춘다.
- 색상 코드 안에 입력 커서가 있을 때는 색상 코드 배경과 대비되는 입력 커서 색을 사용한다.
- 렌더 레이어는 화면에 보이는 줄과 그 주변 줄만 렌더 토큰으로 만든다.
- 자동 줄바꿈은 공백 기준 단어 단위 줄바꿈을 우선하고, 창 너비보다 긴 단일 단어만 표시 폭을 넘기지 않도록 내부에서 접는다.
- 자동 줄바꿈으로 생긴 표시 줄은 원문에 줄바꿈 문자를 추가하지 않으며, 줄 번호는 원문 줄 하나에 하나만 표시한다.
- 색상 코드에 마우스를 올리면 입력 영역 커서를 조작 가능 상태로 바꾼다.
- 색상 코드를 클릭하면 별도 정사각형 색상 필드를 만들지 않고, 숨겨진 앵커를 통해 운영체제 색상 선택기만 연다.
- 색상 선택기의 숨겨진 앵커는 색상 코드의 오른쪽 끝을 기준으로 배치하고, 화면 여백에 따라 위치를 보정한다.
- 색상 선택기의 숨겨진 앵커는 화면에 보이는 픽셀을 남기지 않아야 하며, 색상 코드가 없어지거나 선택기 적용이 끝나면 편집 영역 밖으로 치운다.
- 불리언 값 박스는 좌우 안쪽 여백을 넣되, 같은 크기의 좌우 바깥 여백 보정으로 주변 토큰 위치가 밀리지 않게 한다.
- 자동 쌍 문자 편집 설정이 켜져 있으면 렌더 모드에서 캐럿만 놓인 상태로 여는 괄호나 따옴표를 입력할 때 닫는 짝 문자를 함께 넣고 캐럿을 가운데로 둔다. 캐럿 오른쪽에 이미 닫는 짝 문자가 있어도 반복 입력은 새 쌍을 만들어 중첩 구조로 둔다.
- 자동 쌍 문자 편집 설정이 켜져 있으면 렌더 모드에서 자동 쌍 문자 사이에 캐럿만 있고 안쪽 내용이 비어 있을 때 앞 글자를 지우면 닫는 짝 문자도 함께 지운다. 단, `"""`나 `(()`처럼 바깥 닫힘이 없어 가운데 글자만 감싸진 상태에서는 가운데 글자만 지운다.
- 렌더 모드에서 `Tab`과 `Shift+Tab`은 선택 줄의 들여쓰기 추가와 제거로 동작하고, 줄 앞 들여쓰기 공백 안에서 `Backspace`를 누르면 이전 4칸 경계까지 공백을 한 번에 지운다.
- 화살표 기호 자동 변환 설정이 켜져 있으면 렌더 모드에서 `-->`, `<--`, `<->`, `==>`, `<==`, `<=>`를 공백이나 문서 시작 뒤에 단독으로 입력한 다음 스페이스를 누를 때 각각 `→`, `←`, `↔`, `⇒`, `⇐`, `⇔`로 바꾸고 뒤에 공백을 남긴다.
- 줄바꿈 시 들여쓰기 유지 설정이 켜져 있으면 렌더 모드에서 `Enter`를 누를 때 현재 줄의 선행 공백과 탭을 다음 줄에 복사한다.
- 줄바꿈 시 들여쓰기로 생긴 빈 줄에서 `Backspace`를 누르면 같은 들여쓰기 문자열을 가진 윗줄과 합치고 캐럿을 윗줄 끝으로 옮긴다. 이 동작은 일반 들여쓰기 한 단위 삭제보다 먼저 적용한다.
- 자동 쌍 문자 입력과 삭제, 줄 들여쓰기 추가와 제거, 들여쓰기 공백 삭제, 줄바꿈 시 들여쓰기 유지, 빈 들여쓰기 줄 삭제, 화살표 기호 자동 변환은 각각 하나의 실행 취소 단위로 기록한다.
- 색상 코드 선택기는 선택기를 열 때의 값에서 최종 값까지 하나의 실행 취소 단위로 기록한다. 선택 중 발생하는 중간 색상 변화는 화면에만 반영하고 별도 실행 취소 단계로 쌓지 않는다.
- 데이터 파일 형식의 불리언 값 클릭 편집은 한 번의 토글을 하나의 실행 취소 단위로 기록한다.
- 여러 줄 주석은 닫힘이 나올 때까지 다음 줄 상태를 이어 간다.
- JSON 문자열은 같은 줄 안에서 닫힘이 확인된 경우 문자열 또는 키로 표시하고, 닫힘이 없으면 오류 토큰으로 표시한다.
- JSON 키 깊이는 현재 괄호와 대괄호 중첩 수를 기준으로 계산하며, 가장 바깥 객체의 키를 1단계로 본다.
- YAML 키 깊이는 들여쓰기 깊이를 기준으로 계산하며, 가장 바깥 키를 1단계로 본다.
- YAML 블록 문자열 본문은 다음 줄의 들여쓰기가 블록 문자열 시작 줄보다 깊은 동안 문자열 값으로 표시한다.
- 괄호와 따옴표는 같은 줄 안에서 닫힘이 확인된 경우에만 강조하고, 닫힘이 없으면 일반 텍스트로 둔다.
- 닫힘이 확인된 중첩 요소는 최종 토큰 트리의 바깥쪽에서 안쪽 순서대로 깊이를 다시 계산한다.
- 깊이 색상은 기존 렌더 색상 설정을 재사용하며, 깊이가 색상 우선순위가 된다.
- 키 색상은 키 전용 깊이 색상을 우선 적용하며, 일반 괄호 깊이 색상으로 덮어쓰지 않는다.
- Svelte 템플릿 공백이 실제 글자 폭에 영향을 주지 않도록 토큰 재귀 렌더링 부분은 불필요한 줄바꿈과 공백을 넣지 않는다.
- 강조 색상은 CSS 변수로 주입하고 저장 원문에는 영향을 주지 않는다.

## 성능 기준

- 화면에 보이는 줄 주변만 렌더링하는 가상화 표시를 유지한다.
- 큰 파일에서도 전체 줄을 DOM 요소로 한꺼번에 만들지 않는다.
- 창 폭 변경 중에는 보이지 않는 렌더 배경과 줄번호 갱신을 건너뛰고, 안정화된 뒤 보이는 줄 범위만 다시 렌더링한다.
- 수직 스크롤은 원문 `textarea` 기준으로 동기화한다.
- 렌더 모드는 자동 줄바꿈을 기준으로 표시하므로 일반 텍스트에서는 수평 스크롤을 만들지 않는다.

## Windows 가로 휠

Windows WebView2가 일부 가로 휠 입력을 브라우저 이벤트로 제대로 넘기지 않기 때문에, 백엔드가 `WM_MOUSEHWHEEL` 메시지를 받아 `native-horizontal-wheel` 이벤트로 전달한다. 프론트엔드는 원문 모드처럼 가로 스크롤이 있는 표시 상태에서 이 값을 받아 `textarea`의 가로 스크롤 위치에 반영한다.
