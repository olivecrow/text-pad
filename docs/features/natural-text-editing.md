# 자연스러운 텍스트 편집 지침

[English](natural-text-editing.en.md)

이 문서는 구문 강조나 구조화된 표시를 제공하면서도 사용자가 일반 텍스트 편집기처럼 예측 가능하게 입력할 수 있는 편집기를 만들기 위한 행동 지침이다. `text-pad` 렌더 모드의 현재 편집 계약을 바탕으로 하며, 데스크톱 앱과 웹 서비스에서도 같은 원칙을 적용할 수 있게 작성한다.

여기서 원문은 저장되는 실제 문자열이고, 렌더 표시는 원문 위에 덧씌우는 구문 강조와 구조 표현이다. 캐럿은 글자가 입력될 위치를 나타내는 표시이고, 선택 영역은 다음 편집으로 교체될 원문 범위다.

## 목표

자연스러운 편집은 기능이 많은 편집이 아니라 사용자의 다음 예상을 깨뜨리지 않는 편집이다.

- 입력 결과가 화면에서 보이는 위치와 저장 원문에서 같은 위치에 생겨야 한다.
- 앱이 한 번의 키 입력을 보조하더라도 사용자는 그 전체 결과를 한 동작으로 느껴야 한다.
- 캐럿과 선택 영역은 편집 전후의 의미상 같은 위치를 유지해야 한다.
- 보조 기능이 적용되지 않는 상황에서는 운영체제와 입력 요소의 기본 동작으로 안전하게 돌아가야 한다.
- 렌더 표시는 원문을 몰래 정규화하거나 다시 작성하지 않아야 한다.

## 렌더 배치와 포인터 선택

- 스크롤 끝에서 표시 줄의 실제 높이를 반영해 문서 높이가 늘어나면 끝 위치를 유지한다. 사용자가 위로 스크롤하거나 편집 화면이 바뀌면 끝으로 강제 이동하지 않는다.
- 스크롤 중 표시 줄이나 표가 화면에 들어오고 나가면서 브라우저가 선택 변경을 알리더라도, 원문 선택 범위가 같으면 입력 위치로 화면을 되돌리지 않는다. 표 셀을 포함한 편집 영역에서 휠을 돌리면 입력 직후 예약된 캐럿 자동 표시도 취소한다. 이후 실제 키보드 이동·클릭·편집은 입력 위치를 다시 표시한다.

- 연속된 창 폭 변경 중에도 보이는 텍스트는 현재 폭에 맞춰 즉시 줄바꿈한다. 구문 강조와 줄 번호를 숨기지 않으며, 표시 줄의 실제 높이와 글자 좌표로 줄 위치·캐럿·선택 배경을 갱신한다. 원문과 선택 범위는 유지한다. 화면 밖 줄의 추정과 투명 입력창의 전체 줄바꿈만 폭 변경이 80ms 동안 멈춘 뒤 갱신하고, 포인터 누르기·키보드 이동·입력·조합 입력이 시작되면 그 전에 입력창 폭을 맞춘다. 높이만 변경하면 폭 갱신을 지연시키지 않는다.

- 렌더 모드의 줄바꿈은 공백 경계를 우선해 단어를 다음 표시 줄로 옮긴다. 한 단어가 표시 폭보다 길어 공백에서 접을 수 없을 때만 단어 내부에서 접는다. 하이픈이나 구문 강조 토큰의 경계를 별도 우선 줄바꿈 지점으로 사용하지 않는다. 원문의 줄바꿈은 바꾸지 않는다.
- 화면에 표시한 줄의 실제 높이가 다음 줄 위치, 줄 번호와 스크롤 높이의 기준이다. 원문이나 표시 설정이 바뀌면 크기가 그대로인 표시 줄도 다시 측정한다. 화면 밖 줄의 추정 높이를 실제 표시 줄의 높이로 확정하지 않는다.
- 클릭, Shift+클릭, 드래그의 시작점과 끝점은 모두 보이는 렌더 텍스트에서 원문 위치로 변환한다. 투명 입력창의 별도 줄바꿈 좌표로 선택하지 않는다. 역방향 선택과 편집기 밖 드래그 자동 스크롤을 지원한다.
- 두 번 클릭한 단어도 렌더 텍스트 위치를 기준으로 선택한다. 선택 배경과 캐럿은 같은 렌더 범위에서 그리며, 브라우저의 사용자 정의 강조 기능이 없으면 실제 글자 사각형으로 선택 배경을 그린다.
- 드래그하는 동안 마우스 버튼을 놓기 전부터 선택 배경을 표시한다. 포인터 이동 이벤트로 선택 끝점을 갱신하며, 이미 예약된 그리기를 계속 취소해 표시가 지연되지 않게 한다. 선택 배경색은 현재 테마의 설정을 사용한다.
- 클릭과 드래그는 원문과 실행 취소 기록을 바꾸지 않는다. 선택 후 입력과 실행 취소는 기존 원문 범위 변환과 기록 경로를 사용한다.

## 문서 검색

- Ctrl+F 또는 편집 메뉴의 찾기는 활성 탭의 원문만 검색한다. 탭 제목, 파일 경로, 메뉴와 다른 탭은 검색 대상이 아니다. 대소문자를 구분하지 않는 일반 문자열 검색이며, 같은 본문을 원문 입력층과 렌더층에서 중복 집계하지 않는다.
- 검색창에 현재 결과 번호와 전체 개수를 표시한다. Enter/F3은 다음 결과, Shift+Enter/Shift+F3은 이전 결과로 이동하며 끝에서는 순환한다. Escape로 닫으면 편집기로 돌아간다. 한글 조합 입력을 확정하는 Enter는 결과 이동으로 처리하지 않는다.
- 검색 강조는 렌더 모드에서 실제 표시 글자의 원문 경계와 사각형을 사용한다. 코드·굵은 글씨·인용문·표·자동 줄바꿈도 같은 기준이며, 투명 원문 입력창의 좌표로 강조하지 않는다. 원문 모드와 표 입력칸은 해당 입력 요소의 실제 글꼴·여백·스크롤을 사용한다.
- 검색 결과는 코드 배경·선택 영역과 독립된 노란 계열 색상으로 강조하고, 현재 결과에는 더 진한 배경과 테두리를 표시한다. 설정의 편집기 → 렌더 모드 → 색상에서 일반 결과와 현재 결과의 강조색을 테마별로 지정하며 원문·렌더 모드에 함께 적용한다.
- 결과 이동은 원문 선택 범위만 갱신한다. 문서 내용, 변경 상태와 실행 취소 기록은 바꾸지 않으며, 검색어를 편집하는 실행 취소는 검색창 안에서 처리한다. 탭 전환이나 본문 수정 시 활성 문서의 결과를 다시 계산하고, 스크롤·창 크기 변경 시 강조 위치를 갱신한다.
- 숨긴 서식 표식이나 접힌 내용처럼 표시 글자가 없는 결과는 원문에서 보기 버튼을 제공한다. 사용자가 선택하기 전에는 표시 모드를 바꾸지 않는다.

## 키와 값의 자동 줄바꿈

- 렌더 모드에서 구문 분석기가 키·구분자·값으로 인식한 줄은 두 번째 표시 줄부터 값의 시작 위치에 맞춘다. ENV의 `export API_URL = 값`, INI·Properties·TOML과 JSON·YAML의 키/값에도 같은 기준을 사용한다. 문자열이나 주석 속 `=`·`:`는 구분자로 다시 해석하지 않는다.
- 글꼴·탭·구분자 간격을 포함한 실제 표시 폭을 사용하고 창 폭이나 설정 변경 시 다시 측정한다. 값이 첫 표시 줄에서 시작하지 않거나 접두부가 줄 폭의 80%를 넘으면 일반 줄바꿈을 사용한다.
- 연속 공백과 줄 끝 공백도 각각 폭을 차지하고 다음 표시 줄로 넘어간다. 추가 표시 여백과 자동 줄바꿈은 원문·복사·저장·실행 취소 기록을 바꾸지 않는다. 클릭·드래그·위/아래 방향키·Home/End와 Shift 선택은 실제 표시 위치를 따른다. 원문 모드의 기본 편집은 유지한다.

## 구조화 데이터의 표시 전용 정렬

- 한 원문 줄 안에서 완결된 JSON·JSONC·JSON Lines의 객체/배열, YAML 흐름형 객체/배열, TOML 배열/인라인 테이블, XML 요소 구조는 렌더 모드에서 자동으로 여러 표시 줄에 배치한다. 줄 번호·오류 위치와 JSON Lines 레코드 경계는 원문 기준을 유지한다.
- 표시 줄바꿈, 설정에 따른 들여쓰기와 콜론 뒤 간격은 원문 문자를 추가하거나 바꾸지 않는다. 예를 들어 `{"items":[1,2]}`는 화면에서만 다음처럼 보이고, 복사·저장하면 계속 원래 한 줄이다.

```json
{
    "items": [
        1,
        2
    ]
}
```

- 문자열·주석 안의 구조 기호는 분리하지 않는다. YAML 블록/여러 줄 문자열, TOML 여러 줄 문자열, XML 문자 데이터·CDATA·문장 안 태그를 보존하며, `xml:space="preserve"`가 있는 XML 문서는 펼치기를 생략한다.
- 클릭·드래그·선택 강조·캐럿은 같은 원문 위치를 공유한다. 펼친 줄과 인접 원문 줄의 위/아래 방향키, Home/End, PageUp/PageDown과 Shift 선택은 실제 표시 줄로 이동한다. 두 표시 줄이 공유하는 원문 경계에서는 사용자가 선택한 앞줄 끝 또는 뒷줄 시작에 캐럿을 표시한다. Ctrl 조합은 기존 문서 이동을 유지한다.
- 입력·삭제·붙여넣기는 선택한 원문 범위에만 적용하고 기존 실행 취소 기록을 사용한다. 정렬 표시나 모드 전환은 변경 상태와 실행 취소 기록을 만들지 않는다. 원문 모드 또는 해당 형식의 렌더 표시를 끈 상태에서는 펼치지 않는다.
- 구조가 불완전하거나 괄호가 맞지 않는 줄, 2,000개 표시 줄 또는 64단계 깊이를 넘는 줄은 기본 표시를 유지한다. CSV/TSV는 기존 표를 사용하고 줄 경계에 의미가 있는 일반 텍스트·로그·INI 계열은 임의로 펼치지 않는다. 좁은 창에서도 들여쓰기 너비를 표시 줄의 60% 이내로 제한하고 실제 높이를 다시 측정한다.

## 핵심 원칙

### 원문을 단일 기준으로 둔다

- 저장, 실행 취소, 다시 실행, 선택 영역, 변경 여부의 기준은 항상 원문이다.
- 구문 강조, 들여쓰기 가이드, 자동 줄바꿈, 가상화 표시는 원문에서 파생한다.
- 표시 전용 자동 줄바꿈은 원문에 줄바꿈 문자를 넣지 않는다.
- 사용자가 명시적으로 편집한 범위만 바꾼다. 공백, 줄바꿈, 구분자, 따옴표를 편의상 전체 정규화하지 않는다.

### 사용자 동작을 원자적으로 처리한다

- 하나의 키 입력으로 여러 문자가 추가되거나 삭제되어도 실행 취소 한 번으로 전체가 되돌아가야 한다.
- 변경 전 원문과 선택 영역을 먼저 확보하고, 기능이 끝난 뒤의 원문과 선택 영역을 한 번에 기록한다.
- 중간 계산 상태를 별도 실행 취소 단계로 남기지 않는다.
- 결과 원문이 바뀌지 않은 동작은 실행 취소 기록을 만들지 않는다.

### 캐럿과 선택 영역의 의미를 보존한다

- 줄 앞에 들여쓰기를 추가해도 본문 안의 캐럿은 같은 글자 사이에 남아야 한다.
- 글머리 형식의 길이가 바뀌어도 본문 기준의 캐럿과 선택 영역을 유지한다.
- 선택한 여러 줄을 바꾸면 선택 영역은 새로 추가되거나 제거된 접두부를 반영해야 한다.
- 실행 취소와 다시 실행은 원문뿐 아니라 편집 전후의 캐럿과 선택 영역도 복원해야 한다.

### 보조 기능의 경계를 명확히 한다

- `text-pad`의 편집 보조 기능은 렌더 모드에서만 키 입력을 가로챈다.
- 원문 모드는 여러 줄 입력 요소인 HTML `textarea`의 기본 Tab, Backspace, Enter, 괄호, 따옴표 입력을 그대로 사용한다.
- 렌더 모드 여부는 상위 키 입력 경로에서 한 번만 판단한다. 세부 변환 함수는 호출되면 자기 편집 계산만 수행한다.
- 한글을 포함한 조합 입력 중에는 렌더 모드 편집 보조가 끼어들지 않는다.
- Ctrl, Alt, macOS Command 키에 해당하는 Meta가 결합된 운영체제나 앱 단축키를 일반 문자 보조 기능이 가로채지 않는다.

## 자동 쌍 문자

자동 쌍 문자는 여는 문자를 입력할 때 닫는 문자를 함께 만들고 캐럿을 사이에 두는 기능이다.

현재 쌍은 다음과 같다.

| 여는 문자 | 닫는 문자 |
| --- | --- |
| `(` | `)` |
| `[` | `]` |
| `{` | `}` |
| `"` | `"` |
| `'` | `'` |
| `` ` `` | `` ` `` |

행동 계약은 다음과 같다.

- 자동 쌍 설정이 켜져 있고 선택 영역 없이 캐럿만 있을 때 적용한다.
- 새 자동 쌍은 캐럿이 텍스트 끝에 있거나, 캐럿 오른쪽이 공백 문자 또는 설정한 예외 문자열로 시작할 때만 만든다. 공백 문자는 항상 예외이며 목록에서 제거할 수 없다. 기본 예외 문자열은 `=`와 `:`이고, 나머지 예외 문자열은 렌더 모드 편집 설정에서 추가하거나 제거할 수 있다.
- 허용된 오른쪽 문맥에서 여는 문자 하나를 입력하면 두 문자를 함께 넣고 캐럿을 가운데로 옮긴다. 허용되지 않은 텍스트가 오른쪽에 있으면 자동 쌍 입력을 사용하지 않고 입력한 문자 하나만 `textarea` 기본 동작으로 넣는다.
- 작은따옴표 `'`를 입력할 때 캐럿 바로 앞이 유니코드 글자·결합 문자·숫자이면, 오른쪽 문맥과 관계없이 자동 쌍 생성과 닫는 따옴표 건너뛰기를 적용하지 않는다. 입력한 작은따옴표 하나만 기본 입력으로 넣는다. 예를 들어 `don|`에서 `'`를 입력하면 `don'|`가 되고, `п|`와 `2024|`에서도 하나만 넣는다. 기존 일반 입력 실행 취소 경로를 사용한다.
- 캐럿 오른쪽에 입력한 닫는 괄호, 따옴표, 백틱과 같은 문자가 이미 있으면 원문을 바꾸지 않고 캐럿만 그 문자 뒤로 옮긴다. 따라서 `"`를 두 번 연속 입력하면 `""`만 남고 캐럿은 닫는 따옴표 뒤에 놓인다.
- 줄 시작의 들여쓰기 뒤에서 백틱을 세 번 연속 입력하고 오른쪽 문맥이 새 자동 쌍을 허용하면 세 번째 입력에서 여는 백틱 세 개, 빈 코드 줄, 닫는 백틱 세 개와 그 뒤의 같은 들여쓰기 줄로 확장하고 캐럿은 빈 코드 줄 안에 둔다. 닫는 울타리 직후의 접힌 캐럿 위치는 숨은 백틱 줄이 아니라 그 다음 줄의 첫 편집 위치를 가리키며, 기존 줄바꿈 형식과 들여쓰기를 유지한다.
- 선택 영역이 있으면 현재 구현은 자동으로 감싸지 않고 기본 입력을 사용한다. 선택 영역 감싸기를 추가하려면 별도 행동 계약과 검증을 먼저 정의한다.
- 비어 있는 자동 쌍 사이에서 Backspace를 누르면 여는 문자와 닫는 문자를 함께 지운다.
- HTML·인용문 같은 복합 서식 안에서도 빈 자동 쌍 삭제를 일반 표시 문자 삭제보다 먼저 처리한다.
- `"""`나 `(()`처럼 바깥 닫힘이 확인되지 않는 반복 문자 문맥에서는 주변 문자를 추측해 함께 지우지 않는다.
- 자동 삽입, 쌍 삭제, 백틱 코드 블록 확장은 각각 실행 취소 한 번의 단위다. 원문이 바뀌지 않는 닫는 문자 건너뛰기는 실행 취소 기록을 만들지 않는다.
- 렌더 모드에서는 숨긴 인라인 백틱과 코드 블록 울타리 줄을 접힌 캐럿 위치로 사용하지 않는다. 클릭과 방향키 이동은 인라인 코드의 보이는 경계 또는 코드 블록 안팎의 인접한 편집 줄로 건너뛴다.
- 닫는 울타리 바로 다음 줄의 선행 공백 안에서 Backspace를 누르면 코드 내용과 줄은 유지하고 여는 울타리와 닫는 울타리의 연속 백틱을 각각 두 개로 줄여 코드 블록 문법만 해제한다. 이때 캐럿은 닫는 울타리에 남은 두 백틱 바로 뒤, 즉 제거된 백틱 자리에 둔다. 여닫는 울타리를 모두 포함한 코드 블록 전체 선택 삭제도 허용하며, 울타리 문법 해제는 실행 취소 한 번의 단위다.

## 짝 괄호와 따옴표 강조

렌더 모드에서는 캐럿에 닿은 짝 문자의 반대편을 함께 보여 현재 편집 범위를 바로 확인할 수 있게 한다.

- 대상은 소괄호 `()`, 대괄호 `[]`, 중괄호 `{}`, 큰따옴표 `""`, 작은따옴표 `''`다. 백틱은 인라인·울타리 코드 문법으로 따로 처리하고, `< >`는 비교 연산자나 태그와 충돌하므로 대상에서 제외한다.
- 선택 영역 없이 캐럿만 있고 편집기에 포커스가 있을 때, 캐럿 바로 앞이나 뒤의 대상 문자가 완성된 짝에 속하면 여는 문자와 닫는 문자를 모두 강조한다. 인접한 두 짝이 같은 캐럿 위치에 닿으면 여는 문자 바로 뒤 또는 닫는 문자 바로 앞인 안쪽 경계를 우선한다.
- 괄호는 여러 줄을 지나도 종류와 중첩 순서가 맞는 짝을 찾는다. 서로 맞지 않거나 닫히지 않은 괄호는 추측해 강조하지 않고, 완성된 따옴표 안의 괄호는 구조 괄호로 보지 않는다.
- 큰따옴표와 작은따옴표는 같은 줄 안의 닫힘과 백슬래시 이스케이프를 확인한다. 단어 안의 줄임·소유 표기용 작은따옴표는 짝 따옴표로 보지 않는다.
- 작은따옴표로 감싼 구간은 첫 번째 유효한 닫는 따옴표에서 끝난다. `ABC 'DEF' G 'HI' JKLMN`에서는 `DEF`와 `HI`만 각각 감싸고 중간의 `G`는 일반 텍스트다.
- 완성된 따옴표와 괄호 범위는 안쪽 글자까지 기존 중첩 깊이 색상으로 표시한다. 문자 종류별 색상이 이를 덮어쓰지 않아야 하며, 범위 밖의 일반 글자에는 문자 종류별 색상을 적용한다.
- 선택 영역이 생기거나 편집기 포커스를 잃거나 원문 모드로 전환하면 짝 강조를 지운다. 강조는 화면에 보이는 글자 범위에만 그리며, 가상화된 반대편이 화면에 들어오면 같은 원문 오프셋으로 다시 표시한다.
- 이 기능은 원문, 캐럿 위치, 선택 영역과 실행 취소 기록을 바꾸지 않는 표시 전용 동작이다.

### 작은따옴표와 아포스트로피 판정

- 인용 밖에서 글자·결합 문자·숫자 바로 뒤의 `'`는 단어 내부 또는 끝의 아포스트로피로 보아 새 인용을 열지 않는다. 여러 문자 체계에 공통으로 적용한다.
- 단어 경계에서 열린 인용은 첫 유효한 닫힘까지 감싼다. 닫힘 뒤의 글자나 내부 가장자리 공백은 닫힘을 막지 않는다. `asdfasd 'asdfasdf'asdfasdfsdaf`는 `'asdfasdf'`만 감싸고, `' spaced 'next`는 `' spaced '`만 감싼다.
- 인용 내부의 흔한 축약 접미사·생략 접두사, 키릴 문자 결합, 튀르키예어 고유명사·숫자 뒤의 대표 접미사, 한 단어 안의 추가 닫힘을 확인해 아포스트로피를 건너뛴다. `'don't stop'next`, `'l'homme arrive'ensuite`, `'п'ять слів'далі`는 내부 아포스트로피에서 닫히지 않는다.
- `'s morgens`, `'t huis`, `'tis`, `'90s` 같은 앞 생략형은 새 인용을 열지 않는다. 바로 닫는 짝이 있는 `'s'`, `'t'`, `'90s'`는 인용이다.
- 끝의 소유·생략 표기는 새 인용이 시작되기 전에 별도 닫힘이 있을 때 내부 문자로 유지한다. `'dogs' collars'`와 `'un po' di pane'`는 전체를 감싸고, `'cats' and 'dogs'`는 두 인용으로 나눈다.
- 색상 범위와 캐럿의 짝 강조는 같은 판정을 공유한다. 이스케이프한 따옴표는 경계에서 제외하고 줄바꿈을 넘어 짝을 찾지 않는다. `’`와 `ʼ`를 직선 따옴표로 자동 변환하지 않는다.
- 언어 감지나 완전한 문법 검사는 아니다. `'word's`처럼 인용과 소유 표기가 모두 가능한 경우에는 알려진 아포스트로피 형태를 우선한다. 방언·이름·알려지지 않은 생략형에는 오판 가능성이 있으며, 모호한 인용은 큰따옴표나 공백으로 경계를 명확히 할 수 있다.

| 대표 문맥 | 아포스트로피로 유지하는 예 |
| --- | --- |
| 영어 | `don't`, `John's`, `dogs'` |
| 프랑스어 | `l'homme`, `aujourd'hui`, `qu'il` |
| 이탈리아어 | `l'amico`, `un'amica`, `po'` |
| 카탈루냐어·아일랜드어·이름 | `d'acord`, `l'home`, `d'fhág`, `O'Neill` |
| 튀르키예어 | `Ankara'ya`, `Türkiye'nin`, `2024'te` |
| 키릴 문자 | `п'ять`, `об'єкт`, `аб'ект` |
| 앞 생략형 | `'s morgens`, `'t huis`, `'tis`, `'90s` |

아포스트로피의 모호성은 [Unicode 단어 경계 설명](https://www.unicode.org/reports/tr29/tr29-49.html#Apostrophe)을 참고한다. 대표 형태는 [Cambridge 영어 축약](https://dictionary.cambridge.org/grammar/british-grammar/contractions), [OQLF 프랑스어 생략](https://vitrinelinguistique.oqlf.gouv.qc.ca/21786/lorthographe/elision-et-apostrophe/elision-facultative), [TDK 튀르키예어 아포스트로피](https://tdk.gov.tr/icerik/yazim-kurallari/kesme-isareti/), [Taaladvies 네덜란드어 생략형](https://taaladvies.net/s-avonds-of-s-avonds-hoofdletter/)을 참고한 표시 규칙이며 각 언어 전체의 문법을 구현하지 않는다.

## Markdown 제목 편집

- 렌더 표시가 켜진 `.md`와 `.markdown` 문서에서 줄 첫 공백이 최대 세 칸인 위치의 `# `부터 `###### `까지를 제목 1~6단계로 표시한다.
- 렌더 모드에서 선택 영역 없는 캐럿이 줄 시작의 `#`부터 `######` 바로 뒤에 있을 때 Space를 누르면 공백 한 칸을 붙이고 해당 단계 제목을 즉시 적용한다. 예를 들어 `##|제목`에서 Space를 누르면 `## |제목`이 되고 2단계 제목으로 표시한다. 여기서 `|`는 캐럿이다.
- 캐럿 오른쪽에 공백까지 포함한 기존 제목 표식이 있으면 새로 입력한 표식이 기존 단계를 교체한다. 예를 들어 기존 3단계 제목 앞에 `#`를 입력해 `#|### 기존 제목`이 된 상태에서 Space를 누르면 `# |기존 제목`으로 바뀌고 1단계 제목을 적용한다.
- 기존 제목 단계를 교체하는 동안에는 숨은 기존 표식 앞의 캐럿을 유지해 `#`을 최대 여섯 개까지 연속 입력할 수 있게 한다. Space가 아닌 다른 편집이나 캐럿 이동을 시작하면 이 임시 교체 위치를 해제한다.
- 기본 설정은 제목 앞 표식을 보이지 않게 하지만, 원문과 선택 위치를 보존하기 위해 같은 원문 범위를 숨은 구문으로 유지한다. 울타리 코드 블록 안의 표식은 숨기거나 제목으로 바꾸지 않는다.
- 제목 단계별 크기와 굵기, 표식 숨김, 1·2단계 구분선은 모든 Markdown 문서에 공통인 표시 설정이다. 설정 변경은 원문과 실행 취소 기록을 바꾸지 않는다.
- 링크·HTML을 포함한 제목도 일반 제목과 같은 글자 크기·굵기·표식 숨김·구분선 설정을 따른다. 복합 본문은 편집기의 글자 크기·줄 높이·탭 크기를 공유한다.
- `#` 자체는 일반 문자 입력이다. Space로 제목을 적용하거나 기존 단계를 교체할 때도 최종 원문에는 새 제목 표식과 공백을 Markdown 문법으로 유지하며, 해당 Space 입력과 기존 표식 교체 전체를 실행 취소 한 번의 단위로 기록한다.
- 선택 영역이 있거나 조합 입력 중이거나 Ctrl·Alt·Meta가 눌렸거나, 표식이 줄 시작의 최대 세 칸 선행 공백 뒤에 있지 않거나, 표식이 일곱 개 이상이거나, 울타리 코드 블록 안이거나, 원문 모드이면 제목 적용을 가로채지 않는다.
- 제목 줄을 클릭하거나 방향키로 이동하고 선택할 때는 렌더된 제목 글자의 실제 폭을 원문 위치로 변환한다. 숨은 표식 범위 안에 캐럿이 갇히지 않게 보이는 제목 경계로 이동한다.
- 제목 안의 링크, 강조, 인라인 코드도 원문 범위를 그대로 유지하며, 저장 결과에는 표시용 크기·굵기·색상·구분선을 넣지 않는다.

## Markdown 표

- CSV/TSV와 Markdown 공통 표 편집기는 아무 셀도 선택하지 않은 상태로 시작한다. 셀을 클릭하거나 키보드로 들어갔을 때만 셀·해당 행·열을 선택 강조하고, 입력 초점이 떠나면 강조를 해제한다. 다른 셀로 이동하면 그 셀만 새로 선택하며, 머리글의 기본 구분 색상은 선택 강조와 독립적으로 유지한다.
- 머리글과 파이프 구분 행이 연속된 본문 표는 CSV/TSV와 같은 셀·행·열 편집기로 표시한다. 별도 형식 이름·도구 막대·바깥 테두리 없이 본문에 표를 바로 그린다. 표시와 모드 전환만으로 원문을 바꾸지 않는다. 코드·주석·목록 안의 표와 예산을 넘는 표는 원문으로 남기고, 인용문 안의 표는 인용 영역의 미리보기로 표시한다.
- 셀 선택·캐럿 경계를 이스케이프된 파이프, 문자 참조, `<br>` 줄바꿈을 포함한 실제 원문 위치와 연결한다. 기존 셀 입력은 그 셀 범위만 바꾸고 표 앞뒤 본문과 다른 셀의 공백·구분자는 보존한다. 행·열 조작은 해당 표 범위만 정규화하며 줄바꿈 방식과 열 정렬을 보존한다.
- 같은 표·같은 셀의 연속 입력은 한 실행 취소 묶음이며, 행·열 조작은 각각 독립 단위다. 실행 취소·다시 실행은 원문과 셀 선택 위치를 함께 복원한다. 조합 입력 중에는 셀 이동 키를 가로채지 않는다.
- 표 셀의 붙여넣기·잘라내기·선택 교체는 앞뒤의 일반 입력과 별도 실행 취소 단위다. 한글 조합은 1초 이상 멈추거나 중간 글자를 교체해도 시작부터 확정까지 한 단위이며, 조합 시작·종료와 셀 이탈에서 일반 입력 묶음을 끊는다. CSV/TSV에도 같은 기준을 적용한다.
- `Tab`/`Shift+Tab`으로 셀 사이를 이동하고 표 끝에서는 뒤/앞 본문으로 나간다. `Escape`는 표 뒤로, 첫 행 시작의 위 방향키와 마지막 행 끝의 아래 방향키는 각각 앞/뒤로 이동한다. `Ctrl+Home`/`Ctrl+End`도 표 앞/뒤로 이동한다. 문서 경계에 이동할 본문 줄이 없으면 빈 줄 하나를 만들고 독립 실행 취소 단위로 기록한다.
- 표는 가용 본문 너비를 채우되 최소 500픽셀을 유지하며, 그보다 좁은 영역에서는 표 내부 가로 스크롤을 사용한다. 셀은 내부 스크롤 없이 너비에 맞춰 줄바꿈하며 긴 단어도 나눈다. 각 행과 그 안의 입력칸은 가장 높은 셀에 맞춰 높이를 늘리거나 줄인다. 창·열 너비 변경과 화면 줄바꿈만으로 원문 개행이나 실행 취소 기록을 만들지 않는다. 이 배치는 CSV/TSV 공통 편집기에도 적용한다.
- 열 너비는 머리글을 포함한 모든 셀의 글자 수를 열별로 합산한 뒤 제곱근 비율로 배분하며 개행은 세지 않는다. 글자 수 1:16을 너비 1:4로 보정해 짧은 열이 지나치게 좁아지는 것을 완화한다. 각 열은 최소 100픽셀을 유지하고, 남은 공간을 나머지 열의 보정된 비율로 배분한다. 전체가 빈 표는 균등 배분하며, 열이 많아 최소 너비를 담을 수 없으면 표를 넓혀 가로 스크롤한다. 내용 편집 후에도 자동 배분하되, 직접 너비를 조절한 뒤에는 제곱근 보정 없이 수동 비율과 최소 너비를 우선한다. 너비 변경은 원문과 실행 취소 기록을 바꾸지 않는다.
- 표의 전체 높이가 다음 본문 줄과 스크롤 범위를 결정하며, 긴 표도 문서와 함께 세로로 스크롤한다. 표 밖에서 시작한 원문 선택과 복사는 표 문자열도 포함한다. 셀 안에서는 기존 공통 표 편집기의 텍스트 선택을 사용한다.
- 포커스가 없는 Markdown 셀은 강조·태그·문자 참조·링크·이미지를 안전한 서식으로 표시한다. 셀 본문을 클릭하면 해당 셀의 Markdown 입력값 전체를 선택하고, 키보드 진입은 기존 선택 위치를 사용한다. 포커스를 잃으면 다시 서식을 표시한다. 이 전환은 문서의 원문 모드나 실행 취소 기록을 바꾸지 않는다. 링크와 접기 제목은 기존 동작을 유지한다.
- 태그·문자 참조·강조 이스케이프는 셀 수정과 행·열 이동 후에도 Markdown 의미를 유지한다. `&lt;kbd&gt;`는 문자로 표시하고 `<kbd>`와 구분한다. 코드 밖의 `<br>`는 편집용 줄바꿈으로, 이스케이프된 파이프는 편집용 `|`로 연결하고 실제 원문 경계를 보존한다. 코드 안의 `<br>`는 문자로 유지한다. 미리보기·이미지의 실제 높이와 편집 중 원문 높이를 행 배치에 반영한다. CSV/TSV의 일반 텍스트 편집은 바꾸지 않는다.
- 예: `| 품목 | 수량 |` 다음에 `| :--- | ---: |`와 `| 연필 | 2 |`가 있으면 왼쪽/오른쪽 정렬의 2열 표다. `연필` 셀을 `연필 세트`로 고치면 다른 셀과 표 밖 문장은 그대로이며 실행 취소 한 번으로 `연필`로 돌아간다.

## Markdown 서식과 HTML

- 일반 줄의 굵게·기울임·취소선 표식은 숨겨도 원문 위치를 유지하며, 보이는 글자를 클릭한 위치에서 편집하고 실행 취소한다.
- `**굵게 *중첩 기울임* 끝**`, `*기울임 **중첩 굵게** 끝*`, `***둘 다***`, 따옴표 안의 강조를 해석한다. 단어 안의 밑줄, 이스케이프한 별표, 짝이 맞지 않거나 안쪽에 공백이 붙은 표식은 강조로 바꾸지 않는다. 인라인·울타리 코드 안의 강조 표식은 문자로 남긴다.
- 연속된 `>` 줄은 왼쪽 세로선이 있는 한 인용 영역이며, `>` 빈 줄은 내부 문단을 나누고 `> >`는 중첩 인용문이다. 인용문 안의 강조·목록·표·코드를 함께 표시하고, 표식 없는 이어지는 문장과 영역의 끝은 Markdown 문단 경계를 따른다. 인용문 및 여러 줄에 걸친 강조도 렌더 모드에서 직접 편집하며 기존 원문 줄바꿈을 보존한다.
- HTML, 이미지, 링크, 문자 참조를 포함한 문단과 가로 구분선은 안전한 복합 서식 미리보기로 표시한다. 예: `<p align="center"><strong>제목</strong><br><sub>설명</sub></p>`.
- 복합 영역의 글자도 클릭·Shift+클릭·드래그·두 번 클릭으로 캐럿과 선택 범위를 정하고 렌더 모드를 유지한 채 입력·붙여넣기·실행 취소한다. 표시 경계는 해석기가 소비한 원문 범위로 연결하고, 반복 문구·태그·문자 참조·CRLF 때문에 위치가 달라지지 않아야 한다. 한글 조합 입력은 기존 입력 경로를 유지한다. 경계를 확인할 수 없는 블록만 편집 가능한 원문으로 표시한다.
- 여러 서식에 걸친 부분 선택을 삭제·잘라내기·교체하면 선택한 표시 문자만 바꾸고 숨긴 감싸는 문법은 보존한다. `<b>abc</b><i>def</i>`의 `bcde`를 지우면 `<b>a</b><i>f</i>`가 된다. 전체 블록 또는 문서 전체를 선택한 삭제·교체는 태그도 함께 지운다. 일반 원문 줄바꿈은 서식 태그처럼 보호하지 않는다.
- 감싸는 HTML 태그 안에 글자나 공백이 전혀 없으면 여닫는 태그를 원문 그대로 표시하고 직접 편집한다. `<b></b>`는 그대로 보이고, `<b>글자</b>`와 `<b> </b>`는 서식을 적용한다. 중첩된 빈 태그만 있는 바깥 태그와 아직 짝을 완성하지 않은 태그도 드러낸다. 이미지·줄바꿈처럼 표시 내용을 가진 요소는 빈 내용으로 취급하지 않는다.
- Markdown 링크도 문구가 빈 `[](https://example.com)`은 문법 전체를 표시해 `[]` 안에 입력할 수 있게 한다. 문구가 생기면 링크 서식을 적용한다.
- 서식 경계를 넘는 한글 선택 교체는 조합 중 입력값과 선택 위치를 강제로 고치지 않는다. 조합 확정 때 감싸는 문법을 복원하고 조합 전체와 같은 실행 취소 단위로 기록한다. 수동 편집의 원문과 선택 위치는 다음 키 입력 전에 함께 적용한다.
- 방향키·Home/End는 표시 글자 위치를 따르고, Backspace/Delete는 문자 참조 전체를 포함해 표시 문자 하나를 지우며 태그 내부를 한 글자씩 지우지 않는다. Enter는 HTML 본문에서 `<br>`, Markdown 본문에서 강제 줄바꿈과 현재 인용 접두부, 코드 안에서 원문 줄바꿈을 넣는다. 각각 기존 실행 취소 기록을 사용한다.
- 링크 문구와 접기 제목은 일반 클릭으로 편집하고 Ctrl+클릭(또는 Command+클릭)으로 링크 열기·접기 동작을 실행한다. 열린 접기는 내용 입력 중 유지한다. `‹/›` 버튼은 원문 모드로 돌아가 해당 영역을 선택해 태그·주소 등 문법 자체를 편집한다. 표 셀 미리보기의 링크·접기는 기존 동작을 유지한다.
- `<details><summary>더 보기</summary>…</details>` 접기·펼치기, 이미지 로드와 폭 변경의 실제 높이를 뒤 문단과 스크롤에 반영한다. 접기 상태와 원문 전환은 원문·실행 취소를 바꾸지 않는다.
- 코드 안의 태그는 문자로 유지한다. 문서의 스크립트·이벤트·임의 스타일은 실행하지 않는다. 복합 HTML·인용문 안의 표는 미리보기로 표시하고, 그 밖의 Markdown 표는 기존 셀 편집기를 유지한다.

## 렌더 체크박스

- 일반 텍스트와 Markdown 문서에서 선택적인 선행 들여쓰기 뒤의 첫 콘텐츠가 `[]` 또는 `[V]`이고, 표식 바로 뒤에 일반 스페이스(U+0020)가 들어온 순간부터 각각 선택되지 않은 체크박스와 선택된 체크박스로 표시한다. 울타리 코드 블록 안의 같은 문자열은 체크박스로 해석하지 않는다.
- 스페이스가 없는 `[]`, `[V]`, `[]본문`, `[V]본문`과 스페이스 대신 탭이 이어진 표식은 일반 원문으로 표시한다. 선택 표식은 대문자 `V`만 사용하며, `[v]`, `[x]`, `[ ]`처럼 계약에 없는 표식도 일반 원문으로 표시한다.
- 체크박스 모양은 원문 표식의 실제 글자 노드를 유지한 채 화면용 고정 폭 안에 그린다. `[]`와 `[V]`의 원문 길이가 달라도 최종 체크박스 폭과 뒤 본문의 시작 위치 및 간격은 같아야 하며, 줄바꿈과 캐럿 좌표도 이 최종 화면 배치를 기준으로 계산한다.
- 렌더 모드에서 체크박스를 클릭하면 해당 표식만 `[]`와 `[V]` 사이에서 바꾸고, 표식 뒤의 필수 스페이스를 포함한 같은 줄의 나머지 원문은 유지한다. 원문 모드의 클릭과 기본 텍스트 편집은 가로채지 않는다.
- 표식 길이가 2자와 3자 사이에서 바뀌므로 표식 뒤의 캐럿과 선택 영역은 그 길이 차이만큼 이동하고, 표식 안의 위치는 새 표식 범위 안으로 보정한다.
- 선택 영역이 접혀 있고 캐럿이 표식과 필수 스페이스 뒤에 있을 때 일반 `Enter`를 누르면 현재 줄을 캐럿에서 나누고 다음 줄을 같은 선행 들여쓰기와 새로운 미선택 표식 `[] `로 시작한다. 현재 항목이 `[V]`로 선택되어 있어도 새 항목은 `[] `다.
- 선행 들여쓰기와 `[] ` 또는 `[V] `만 있는 빈 항목의 끝에서 일반 `Enter`를 누르면 새 항목을 만들지 않고 현재 표식과 필수 스페이스만 제거해 체크박스 목록을 끝낸다. 기존 선행 들여쓰기는 유지하며, `Shift+Enter`는 다음 체크박스를 만들지 않는 일반 줄바꿈으로 유지한다.
- 자동 이어쓰기와 빈 항목 종료는 현재 문서의 CRLF 또는 LF 줄바꿈을 보존한다. 한 번의 체크·체크 해제·자동 이어쓰기·빈 항목 종료는 각각 하나의 실행 취소 단위이며, 실행 취소와 다시 실행은 원문과 선택 영역을 함께 복원한다.

## 들여쓰기와 내어쓰기

Tab은 캐럿 자리에 공백을 넣는 문자가 아니라 현재 줄의 구조를 한 단계 깊게 만드는 명령으로 취급한다.

- 선택 영역이 없으면 캐럿이 있는 줄 전체를 들여쓴다.
- 선택 영역이 있으면 선택에 걸친 모든 줄을 한 번에 들여쓴다.
- 들여쓰기 한 단계는 현재 네 칸 공백이다.
- 원문 길이가 0인 완전히 빈 줄도 일반 줄과 같은 들여쓰기 대상이다. Tab을 누르면 한 단계 들여쓰기를 추가하고 캐럿을 그 뒤에 두어 다음 텍스트 입력이 들여쓴 위치에서 시작하게 한다.
- Shift+Tab은 선행 탭 하나 또는 선행 공백 최대 네 칸을 제거한다.
- 선행 공백이 없는 줄에서 Shift+Tab을 눌러도 원문이나 실행 취소 기록을 바꾸지 않는다.
- 줄 본문의 캐럿과 선택 영역은 접두부 길이 변화만큼 이동해 같은 본문 위치를 가리켜야 한다.
- 줄 앞 들여쓰기 안에서 Backspace를 누르면 한 글자씩 지우지 않고 이전 네 칸 경계까지 지운다. 탭 문자는 한 번에 하나를 지운다.
- Tab은 본문 안에 캐럿이 있어도 줄 전체에만 적용하고 본문 중간에 공백을 삽입하지 않는다. Backspace는 선행 들여쓰기 밖에서 기본 삭제 동작을 유지한다.
- 체크박스 줄의 Tab과 Shift+Tab은 선행 들여쓰기만 추가하거나 제거하고 `[]`·`[V]` 표식과 현재 체크 상태를 그대로 유지한다.
- 한 번의 Tab이나 Shift+Tab으로 여러 줄과 글머리가 함께 바뀌어도 실행 취소 단위는 하나다.

## 글머리 기호

### 인식

글머리는 줄의 선행 공백 뒤에서 시작하며, 표식 뒤에 공백이나 탭이 최소 하나 있어야 한다.

현재 인식하는 형태는 다음과 같다.

- 숫자: `1. `, `1) `, `(1) `
- 한 글자 영문자: `A. `, `a) `, `(a) `
- 유효한 로마 숫자: `I. `, `II. `, `iv. `
- 순서 없는 표식: `- `, `* `, `+ `, `• `

`-`, `*`, `+`는 가벼운 마크업에서 널리 쓰이는 표식이고, `•`는 일반 문서에서 자주 쓰이는 글머리다. 표식과 본문 사이의 공백은 글머리의 일부로 취급해 이어쓰기 때 그대로 보존한다. 줄 중간에 있는 같은 문자열은 글머리로 취급하지 않는다.

### 렌더 본문 칸과 경계 편집

- 렌더 모드에서 인식한 글머리 줄은 표식 칸과 본문 칸으로 이루어진 두 열 격자로 배치한다. 본문 칸은 표식 뒤에 공백을 그려 넣은 위치가 아니라 독립된 줄바꿈 폭을 가진 실제 레이아웃 영역이다.
- 모든 순서 있는·없는 글머리는 현재 렌더 글꼴의 공백 네 칸을 측정한 만큼 줄 전체를 오른쪽으로 들여서 표시한다. 기존 선행 들여쓰기에는 이 여백을 한 번만 더하고, 자동 줄바꿈과 `Shift+Enter` 연속 줄에도 같은 여백을 적용한다. 원문과 연속 줄의 구조 공백에는 표시 여백을 추가하지 않으며, 모드 전환·복사·저장·실행 취소 기록에도 포함하지 않는다.
- 표시 여백은 캐럿이 머물거나 선택할 수 있는 글자가 아니다. 여백 클릭은 해당 표시 줄의 본문 시작으로 연결한다. 글머리 줄과 연속 줄에서는 목록의 중첩 깊이만으로 구분선을 만들지 않고 앞선 일반 줄의 바깥 들여쓰기 구분선만 이어 그린다. 목록이 더 깊어져도 구분선을 추가하지 않으며, 더 얕아지면 벗어난 단계의 구분선을 끝낸다. 들여쓰기 없는 빈 줄이나 코드 블록을 만나면 상속을 끝내고, 다음 일반 줄에서는 그 줄의 들여쓰기를 기준으로 새로 시작한다. 이어받은 구분선은 일반 줄과 같은 문서 왼쪽 기준점에서 그린다. 모든 구분선은 설정된 테마 색상에 불투명도 50%를 적용한다. 표시 여백 자체에는 구분선을 만들지 않는다. 화면 밖 줄의 높이 추정과 실제 본문 칸은 모두 이 여백을 뺀 줄바꿈 폭을 사용하고, 캐럿·선택 영역은 최종 렌더 글자 좌표를 따른다.
- 자동 줄바꿈 경계의 접힌 글자 범위를 브라우저가 앞줄 끝으로 반환하더라도, 다음 글자가 실제로 다음 표시 줄에 있으면 그 글자의 왼쪽 경계를 캐럿과 클릭 좌표로 사용한다. 여백 클릭이 첫 글자 뒤로 밀리지 않아야 한다.
- 첫 줄 본문, 자동 줄바꿈으로 생긴 표시 줄, `Shift+Enter` 연속 줄은 모두 같은 본문 칸의 왼쪽 경계를 사용한다. 연속 줄의 선행 공백은 원문 호환용 구조로만 남고 렌더 본문의 편집 가능한 공백이나 들여쓰기 단계로 취급하지 않으므로, 이 구조 공백에는 들여쓰기 구분선을 표시하지 않는다. 앞선 일반 줄에서 이어받은 바깥 구분선만 유지한다.
- 표식 칸이나 연속 줄의 구조 영역을 클릭하면 접힌 캐럿을 본문 시작으로 보정한다. 구조 영역에는 접힌 캐럿을 두지 않으며, 연속 줄 본문 시작에서 `ArrowLeft`를 누르면 구조 공백을 순회하지 않고 윗줄 끝으로 이동한다.
- 글머리 첫 줄의 본문 시작에서 `Backspace`를 누르면 표식의 마지막 보이는 문자와 표식 뒤 구조 간격을 함께 제거한다. 따라서 `1. body`는 마침표부터 지워져 `1body`가 되고 글머리 적용이 풀리며, `• body`는 한 번에 `body`가 된다.
- 연속 줄 본문 시작에서 `Backspace`를 누르면 앞 줄바꿈과 연속 줄 구조 영역을 함께 제거해 윗줄 본문과 합친다.
- 표식 끝 문자 제거와 연속 줄 합치기는 각각 실행 취소 한 번의 단위다.

### 들여쓰기 깊이와 형식

글머리 줄을 들여쓰거나 내어쓰면 목표 깊이와 글머리 계열을 기준으로 형식을 다시 선택한다. 순서 있는 글머리는 다음 형식을 사용한다.

| 깊이 | 형식 | 예 |
| ---: | --- | --- |
| 0 | 로마자 대문자와 마침표 | `I. Title1` |
| 1 | 알파벳 대문자와 마침표 | `A. Title2` |
| 2 | 숫자와 마침표 | `1. Title3` |
| 3 | 로마자 소문자와 마침표 | `i. Title4` |
| 4 | 알파벳 소문자와 마침표 | `a. Title5` |
| 5 | 숫자와 오른쪽 괄호 | `1) Title6` |
| 6 | 알파벳 소문자와 오른쪽 괄호 | `a) Title7` |
| 7 | 괄호로 감싼 숫자 | `(1) Title8` |
| 8 | 괄호로 감싼 알파벳 소문자 | `(a) Title9` |

깊이 9부터는 숫자와 알파벳 소문자를 한 쌍으로 두고 구분자를 다음 순서로 반복한다.

1. 마침표: `1. `, `a. `
2. 오른쪽 괄호: `1) `, `a) `
3. 양쪽 괄호: `(1) `, `(a) `
4. 다시 마침표

순서 없는 글머리는 순서 있는 글머리와 섞지 않고 `- `, `* `, `+ `, `• ` 순서로 깊이마다 순환한다. 깊이 4부터는 다시 `- `로 돌아간다.

탭 문자가 섞여 있으면 현재 네 칸 단위의 다음 탭 정지점까지를 시각적 들여쓰기 칸으로 계산한다. 두 계열 모두 기존 표식이 무엇이었는지보다 이동한 뒤의 목표 깊이를 우선한다.

### Enter로 다음 항목 만들기

- 선택 영역 없이 캐럿만 있고, 캐럿이 글머리 표식 뒤에 있을 때만 자동 이어쓰기를 적용한다.
- 현재 줄이 선행 들여쓰기와 글머리 표식만으로 이루어진 빈 항목이고 캐럿이 줄 끝에 있으면, 일반 `Enter`는 새 항목을 만들지 않고 현재 글머리 표식과 표식 뒤 공백을 제거해 목록을 끝낸다.
- 목록을 끝낼 때 새 줄은 추가하지 않는다. 최상위 항목은 빈 일반 줄이 되고, 중첩 항목은 기존 선행 들여쓰기만 남기며 캐럿을 그 뒤에 둔다.
- 빈 일반 줄이 자동 순서 범위의 경계가 되므로 뒤에 이미 있는 글머리 항목의 순번은 바꾸지 않는다. `Shift+Enter`는 이 동작 대신 기존처럼 글머리 없는 연속 줄을 만든다.
- 현재 들여쓰기, 구분자, 표식 뒤 공백을 그대로 유지한다.
- 숫자는 다음 숫자로, 알파벳은 다음 글자로, 로마 숫자는 다음 로마 숫자로 증가시킨다.
- 순서 없는 글머리는 현재 기호를 그대로 사용해 같은 깊이의 다음 항목을 만든다.
- 한 글자 표식은 로마 숫자와 알파벳이 겹칠 수 있다. 같은 깊이와 구분자를 가진 바로 윗줄의 연속성을 먼저 참고하고, 앞선 단서가 없으면 `I`와 `i`는 로마 숫자 시작으로, 다른 한 글자는 알파벳으로 판단한다.
- 다음 표식을 안전하게 계산할 수 없으면 원문을 추측해 바꾸지 않고 기본 Enter 동작으로 돌아간다.
- 캐럿 뒤에 본문이 있으면 줄을 나눈 뒤 그 본문을 새 글머리 뒤로 이동한다.
- 새 항목 뒤에 같은 들여쓰기 깊이와 같은 구분자를 가진 연속된 순서 있는 항목이 있으면 해당 순번을 하나씩 증가시킨다. 중간의 더 깊은 하위 항목과 `Shift+Enter` 연속 줄은 유지하면서 다음 같은 깊이 항목을 계속 찾는다.
- 빈 줄, 같은 깊이나 더 얕은 일반 문단, 같은 깊이의 다른 구분자나 순서 없는 기호, 이미 끊긴 순번을 만나면 자동 순서 범위를 끝낸다. 이 경계 뒤의 원문은 바꾸지 않는다.
- 현재 파일이 Windows식 CRLF 줄바꿈을 사용하면 새 줄도 CRLF를 사용하고, Unix식 LF 파일이면 LF를 사용한다.

예:

```text
1. before|after
2. second
3. third
```

Enter 결과:

```text
1. before
2. |after
3. second
4. third
```

구분자가 다른 경우에도 같은 원칙을 적용한다.

```text
1) before|after
```

Enter 결과:

```text
1) before
2) |after
```

순서 없는 글머리는 같은 기호를 이어 쓴다.

```text
- before|after
- next
```

Enter 결과:

```text
- before
- |after
- next
```

빈 항목에서 Enter로 목록을 끝내는 경우:

```text
1. before
2. |
3. after
```

Enter 결과:

```text
1. before
|
3. after
```

글머리 이어쓰기, 캐럿 뒤 본문 이동, 뒤따르는 항목의 자동 순서 변경 전체는 실행 취소 한 번으로 되돌린다. 빈 항목의 글머리 제거도 별도의 실행 취소 한 번으로 되돌린다.

### Shift+Enter로 같은 항목 안에서 줄바꿈

- 선택 영역 없이 캐럿만 있고, 캐럿이 글머리 표식 뒤에 있을 때 `Shift+Enter`를 누르면 새 글머리 없이 같은 항목의 연속 줄을 만든다.
- 연속 줄의 선행 공백은 현재 렌더 글꼴에서 글머리 본문이 시작하는 실제 폭을 측정하고, 가장 가까운 공백 경계에 맞춘다. 선행 탭과 표식 뒤 탭이 있으면 현재 탭 너비도 함께 반영한다.
- 캐럿 뒤의 본문은 새 연속 줄로 이동하며, 뒤 항목의 순번은 바꾸지 않는다.
- 글머리 없는 연속 줄에서 보조 키 없이 `Enter`를 누르면, 빈 줄이나 더 얕은 일반 문단 없이 이어진 앞선 글머리 중 본문 시작 위치가 현재 들여쓰기와 일치하는 항목을 찾는다.
- 소유 글머리를 찾으면 그 글머리의 다음 항목을 만들고, 연속된 뒤 항목은 같은 자동 순서 범위 규칙으로 다시 번호를 맞춘다. 찾지 못하면 일반 들여쓰기 유지로 돌아간다.
- 연속 줄에서 다시 `Shift+Enter`를 누르면 새 글머리 없이 같은 들여쓰기의 연속 줄을 하나 더 만든다.
- 현재 파일의 CRLF 또는 LF 줄바꿈 형식을 유지한다.

예:

```text
1. before|after
2. next
```

Shift+Enter 결과:

```text
1. before
    |after
2. next
```

연속 줄에 본문을 입력한 뒤 Enter를 누르는 경우:

```text
1. before
    continuation|
2. next
```

Enter 결과:

```text
1. before
    continuation
2. |
3. next
```

`Shift+Enter` 연속 줄 생성과, 그 연속 줄에서 일반 `Enter`로 다음 글머리를 만들고 뒤 항목 순번을 바꾸는 각 동작은 각각 실행 취소 한 번으로 되돌린다.

## Enter와 빈 들여쓰기 줄

글머리가 아닌 들여쓰기된 줄에서도 새 줄은 문맥을 유지해야 한다.

- 줄바꿈 시 들여쓰기 유지 설정이 켜져 있으면 현재 줄의 선행 공백과 탭을 새 줄에 복사한다.
- 선택 영역이 있으면 선택 영역을 줄바꿈과 들여쓰기로 한 번에 교체한다.
- 자동으로 만든 들여쓰기만 남은 빈 줄의 끝에서 Backspace를 누르면 윗줄과 합치고 캐럿을 윗줄 끝으로 옮긴다.
- 빈 들여쓰기 줄 합치기는 일반 들여쓰기 한 단계 삭제보다 먼저 판단한다.
- 글머리 `Shift+Enter` 연속 줄은 글머리 자동 이어쓰기보다 먼저 판단한다.
- 빈 글머리 항목의 일반 `Enter` 목록 종료는 글머리 자동 이어쓰기보다 먼저 판단한다.
- 글머리 연속 줄의 일반 `Enter`는 소유 글머리의 다음 항목 만들기로 먼저 판단한다.
- 글머리 자동 이어쓰기와 연속 줄의 다음 항목 만들기 및 자동 순서 변경은 일반 들여쓰기 유지보다 먼저 판단한다.
- 각 Enter 보조와 빈 줄 합치기는 독립된 실행 취소 한 번의 단위다.

## JSON·JSONC 괄호 사이 Enter

JSON과 JSONC의 빈 객체·배열은 내용을 바로 입력할 수 있는 구조로 펼쳐져야 한다.

- 렌더 표시와 렌더 편집이 켜진 JSON 또는 JSONC에서 선택 영역 없는 캐럿이 구조 중괄호 `{|}` 또는 대괄호 `[|]` 바로 사이에 있을 때 보조 키 없는 `Enter`를 누르면 세 줄 구조로 펼친다. 여기서 `|`는 캐럿이다.
- 여는 괄호 앞 원문은 현재 줄에 유지하고, 둘째 줄은 현재 줄의 선행 들여쓰기보다 한 단계 깊은 네 칸 공백을 추가한 위치에 캐럿을 둔다. 닫는 괄호와 그 뒤의 모든 원문은 셋째 줄로 옮기고 현재 줄의 기존 선행 들여쓰기를 적용한다.
- 현재 문서의 CRLF 또는 LF 줄바꿈을 보존한다. 줄바꿈 시 들여쓰기 유지 설정이 꺼져 있어도 JSON 구조 안쪽의 한 단계 들여쓰기는 기본으로 적용한다.
- JSON 문자열이나 JSONC 주석 안의 괄호, 서로 맞지 않거나 바로 붙어 있지 않은 괄호에는 적용하지 않는다. 한 줄에 JSON 값 하나를 유지해야 하는 JSON Lines와 원문 모드는 기본 `textarea` 줄바꿈을 사용한다.
- 괄호 펼치기와 최종 캐럿 배치를 실행 취소 한 번의 단위로 기록한다.

예:

```json
{|}
```

Enter 결과:

```json
{
    |
}
```

## 문맥 기반 자동 변환

문자열 자동 변환은 사용자가 변환 의도를 확정하는 구분 입력이 들어왔을 때만 실행한다.

현재 화살표 변환은 문서 시작이나 공백 뒤에 다음 문자열을 단독으로 입력한 뒤 Space를 눌렀을 때 적용한다.

| 입력 | 결과 |
| --- | --- |
| `-> ` | `→ ` |
| `--> ` | `→ ` |
| `<- ` | `← ` |
| `<-- ` | `← ` |
| `<-> ` | `↔ ` |
| `<--> ` | `↔ ` |
| `==> ` | `⇒ ` |
| `<== ` | `⇐ ` |
| `<=> ` | `⇔ ` |
| `<==> ` | `⇔ ` |

- 단어 한가운데나 다른 문자에 붙은 문자열은 바꾸지 않는다.
- 변환 뒤에도 사용자가 누른 공백을 하나 남긴다.
- 선택 영역이 있거나 조합 입력 중이면 자동 변환하지 않는다.
- 문자열 교체와 공백 입력 전체를 실행 취소 한 번으로 기록한다.

## 텍스트 복제

`Ctrl+D`는 편집기에 포커스가 있을 때 원문 모드와 렌더 모드에서 같은 복제 명령으로 동작한다.

- 선택 영역이 없으면 캐럿이 있는 원문 줄 전체를 바로 아랫줄에 복제한다. 캐럿은 복제된 줄의 같은 열로 이동한다.
- 현재 줄 뒤에 줄바꿈이 있으면 그 줄의 LF 또는 CRLF를 그대로 복제한다. 문서의 마지막 줄이면 문서에서 선호하는 줄바꿈을 사이에 추가한다.
- 한 줄에서 텍스트를 선택했으면 선택한 문자열만 선택 끝 바로 뒤에 삽입하고, 새로 삽입된 복사본을 선택한다. 예를 들어 `ABCD`에서 `BC`를 선택해 복제하면 `ABCBCD`가 된다.
- 선택이 여러 줄에 걸치면 줄 단위로 넓히지 않고, 줄바꿈을 포함해 정확히 선택된 원문 범위만 선택 끝 바로 뒤에 삽입한다. 새 복사본을 결과 선택 영역으로 둔다.
- 조합 입력 중이거나 설정 입력처럼 편집기 밖에 포커스가 있으면 가로채지 않는다.
- 줄 또는 선택 영역 복제 전체를 독립된 실행 취소 한 번의 단위로 기록한다. 실행 취소와 다시 실행은 편집 전후의 캐럿 또는 선택 영역도 함께 복원한다.

## 실행 취소와 다시 실행

자체 편집 기능이 있는 앱은 브라우저 실행 취소 기록과 앱 상태를 섞지 않고 하나의 기록 체계를 원본으로 삼아야 한다.

`text-pad`는 탭별 자체 기록을 사용한다.

- 탭별 기록은 최대 500개 트랜잭션과 변경 문자열 추정치 16 MiB 안에서 유지한다. 오래된 기록을 제거해 저장 위치를 재현할 수 없게 되거나 편집 한 번이 용량 상한을 넘으면 현재 원문은 유지하되 문서를 변경 상태로 둔다.

- 각 기록은 실제로 바뀐 원문 범위, 변경 전후 문자열, 변경 전후 선택 영역을 저장한다.
- 일반 문자 입력, 연속 Backspace, 연속 Delete는 같은 위치에서 1초 안에 이어질 때 하나의 묶음으로 합친다.
- 한글 같은 조합 입력은 중간 글자의 선택·교체와 대기 시간에 관계없이 시작부터 확정까지 한 실행 취소 단위로 묶고, 조합 앞뒤 일반 입력과 구분한다.
- 붙여넣기, 잘라내기, 메뉴 삭제, 줄바꿈, 줄 또는 선택 영역 복제, 자동 쌍, 백틱 코드 블록 확장과 울타리 문법 해제, Markdown 제목 적용과 단계 교체, 들여쓰기, 글머리 변환처럼 의미가 분명한 편집은 각각 독립된 한 동작으로 기록한다.
- 캐럿 이동, 선택 변경, 포커스 이동, 모드 전환, 설정 변경은 원문을 바꾸지 않으므로 기록하지 않는다.
- 새 앱 전용 편집이 시작되면 진행 중인 일반 입력 묶음을 닫는다.
- 실행 취소 뒤 새 편집을 시작하면 그 위치 이후의 다시 실행 기록을 버린다.
- 저장 시점은 별도 불리언 값이 아니라 현재 실행 취소 위치로 표시한다. 저장 위치와 현재 위치가 다르면 변경된 문서다.
- 브라우저의 `historyUndo`와 `historyRedo` 입력은 앱의 실행 취소와 다시 실행으로 연결한다.

## 렌더 표시와 입력 위치 일치

렌더 배경과 실제 입력 요소를 겹치는 편집기는 두 레이어를 하나의 좌표계처럼 관리해야 한다.

- 글꼴, 글자 크기, 줄 높이, 탭 크기, 패딩, 줄바꿈 폭, 스크롤 위치를 두 레이어에서 같게 유지한다.
- 들여쓰기 가이드의 가로 위치는 CSS `ch`처럼 실제 공백 폭과 다를 수 있는 문자 단위로 추정하지 않는다. 현재 렌더 글꼴에서 각 들여쓰기 칸이 차지하는 실제 폭을 측정해, 비례폭 글꼴에서도 가이드가 해당 선행 공백 위치에 놓이게 한다.
- 자동 줄바꿈은 같은 단어 분리 규칙을 사용하고 원문에는 줄바꿈을 추가하지 않는다.
- 창 크기 변경으로 줄바꿈 계산이 불안정한 동안에는 오래된 렌더 배경보다 실제 입력 텍스트를 우선한다.
- 선택 중에도 구문 강조를 유지하되, 선택 배경은 렌더 레이어의 실제 글자 경계로 그려 실제 선택 배경과 글자 위치가 어긋나지 않게 한다. 일반 글꼴과 고정폭 글꼴이 섞인 선택도 각 렌더 글꼴의 폭을 그대로 따른다. 줄바꿈이나 빈 줄만 선택해 렌더 글자 범위가 하나도 없으면 기본 `textarea` 선택 배경을 유지하고, 실제 커스텀 범위가 등록된 경우에만 기본 선택 배경을 숨긴다.
- 커스텀 캐럿과 클릭 위치는 글자 수나 평균 글자 폭을 다시 계산하지 않고, 브라우저가 최종 배치한 렌더 텍스트 노드의 실제 DOM 범위에서 가져온다. 캐럿의 가로·세로 위치와 높이도 이 범위를 그대로 사용하며, 추정 줄 격자에 다시 맞추거나 별도 줄 높이로 덮어쓰지 않는다. 글머리 본문은 표식 칸 사이의 레이아웃 전용 공백 노드를 좌표 계산에서 제외하고 본문 칸의 텍스트 범위만 사용한다. 브라우저의 기본 좌표 변환을 우선 사용하고, 지원되지 않을 때만 이진 탐색으로 가까운 DOM 범위를 찾는다. 긴 한 줄의 모든 글자 경계를 배열로 만들거나 순회하지 않는다. 줄 끝의 빈 렌더 노드는 건너뛰고 마지막 실제 글자의 오른쪽 경계를 사용해, 원문 줄과 문서의 마지막 위치에서도 캐럿이 보여야 한다.
- 화면에 표시된 원문 줄의 높이는 최종 줄바꿈 결과를 실측해 다음 원문 줄과 줄 번호의 위치에 반영한다. 화면 밖 가상화 구간의 폭 추정치는 초기 배치에만 사용하고, 줄이 화면에 들어오면 실측 높이로 교체한다.
- 렌더 모드의 세로 스크롤 범위는 원문 입력 영역의 일반 줄바꿈 높이나 렌더 조건별 추가 여백으로 만들지 않는다. 코드 블록 안쪽 여백, 제목 크기, 목록 배치 등 모든 표시가 반영된 최종 렌더 줄 높이 합계에 편집 영역 위아래 여백을 더한 값을 하나의 스크롤 표면 높이로 사용하며, 마지막 렌더 줄까지 스크롤할 수 있어야 한다. 입력 영역 위의 일반 세로 휠 입력도 이 최종 렌더 스크롤 표면으로 전달한다.
- 휠, 스크롤바 드래그, 터치패드처럼 사용자가 직접 뷰포트를 움직일 때는 캐럿 좌표와 표시 여부만 새 스크롤 위치에 맞춰 갱신하고, 화면 밖 캐럿을 다시 보이게 하려고 스크롤 위치를 되돌리지 않는다. 캐럿을 화면에 보이게 하는 동작은 키보드 이동, 클릭, 편집처럼 캐럿 위치가 실제로 바뀐 입력 뒤에만 수행한다.
- 인라인 코드와 백틱 코드 블록은 기본적으로 고정폭 글꼴로 표시하되 본문과 같은 글자 크기와 줄 높이를 사용한다. 인라인 코드는 양쪽 백틱 사이에 공백이 아닌 내용이 있을 때만 백틱을 숨기고, 내용이 없거나 공백뿐이면 백틱을 보여 빈 코드 영역임을 알 수 있게 한다. 여러 줄 코드 블록의 여닫는 울타리 줄은 렌더 모드에서 보이지 않게 하되 원문 좌표 계산을 위한 자리는 유지하고, 접힌 캐럿이 숨은 구문 안에 머물지는 않게 한다. 코드 블록 채우기는 숨긴 울타리 줄의 전체 높이 대신 위아래 약 12px만 사용하고 편집 영역 좌우에서 약 12px 안쪽에 배치하며, 배경 안에서도 코드 텍스트와 좌우 가장자리 사이에 약 12px의 안쪽 여백을 유지한다. 여러 줄 코드 블록은 여는 울타리부터 닫는 울타리까지 연속된 하나의 채우기 배경으로 묶고 별도 아웃라인은 그리지 않으며, 코드 텍스트와 선택 강조는 채우기 위에 표시한다. 코드 기본 글자색은 내부 괄호, 글머리 기호, 문자열, 숫자와 같은 구문 색상보다 낮은 우선순위로 적용하며 다크 테마의 기본 코드 글자색은 채도를 낮춘다. 코드 배경색과 기본 글자 색상은 라이트·다크 테마별 색상 설정에서 바꿀 수 있다. 일반 글꼴과 고정폭 글꼴이 한 줄에 섞여도 실제 렌더 DOM 범위로 클릭 위치와 캐럿 위치를 계산한다.
- Windows CRLF 원문과 브라우저 `textarea`의 LF 선택 위치 사이를 양방향으로 변환한다. 원문이 바뀔 때 줄 시작과 CRLF 위치 인덱스를 한 번 만들고 이진 탐색으로 변환하며, 입력 이벤트마다 문서 시작부터 다시 훑지 않는다.
- 원문 위치와 화면 위치 변환은 편집 전후, 실행 취소, 다시 실행, 탭 전환에서 같은 함수를 사용한다.

## 입력 처리 우선순위

같은 키를 여러 기능이 처리할 수 있으므로 더 구체적인 문맥을 먼저 판단한다.

현재 렌더 모드의 우선순위는 다음과 같다.

공통 편집 단축키인 `Ctrl+D`는 원문·렌더 모드에서 먼저 독립된 복제 명령으로 처리하며, 아래 우선순위는 Ctrl, Alt, Meta가 없는 렌더 모드 편집 보조 입력에 적용한다.

각 편집 보조 명령은 고유 식별자와 중복될 수 없는 정수 우선순위를 등록한다. `EditorCommandPipeline`은 등록 배열의 위치와 무관하게 이 값을 기준으로 명령을 정렬하고, 적용된 첫 명령에서 처리를 끝낸다. 새 명령은 기존 명령 사이의 의도한 위치를 우선순위로 명시해야 하며, 식별자나 우선순위가 겹치면 앱 초기화 단계에서 오류로 처리한다.

1. 코드 블록 울타리를 일부만 포함한 선택 삭제 차단
2. 코드 블록 바로 다음 줄의 Backspace 울타리 문법 해제
3. 코드 블록 울타리 옆 줄바꿈의 단일 삭제 차단
4. 빈 자동 쌍의 Backspace
5. 복합 서식의 표시 경계 이동·삭제·Enter
6. 글머리 연속 줄의 본문 시작에서 ArrowLeft로 이전 줄 끝 이동
7. 글머리 Shift+Enter 연속 줄
8. 체크박스 Enter 이어쓰기 또는 빈 항목 종료
9. 빈 글머리 항목 Enter의 목록 종료
10. 글머리 Enter 이어쓰기와 자동 순서 변경
11. 글머리 연속 줄 Enter의 다음 항목 만들기와 자동 순서 변경
12. JSON·JSONC 구조 괄호 사이 Enter 펼치기
13. 일반 줄의 Enter 들여쓰기 유지
14. 글머리 본문 시작의 Backspace 표식 끝 문자 제거
15. 글머리 연속 줄 본문 시작의 Backspace 줄 합치기
16. 자동 들여쓰기만 남은 빈 줄의 Backspace 합치기
17. Tab과 Shift+Tab 줄 들여쓰기
18. 선행 들여쓰기 안의 Backspace
19. Space로 확정하는 Markdown 제목 적용과 기존 단계 교체
20. Space로 확정하는 문맥 기반 자동 변환
21. 여는 문자의 자동 쌍 입력, 같은 닫는 문자 건너뛰기, 세 번째 백틱의 코드 블록 확장
22. 위 조건에 맞지 않으면 기본 `textarea` 입력

보조 함수 안에서 다른 보조 기능을 연쇄 호출하지 않는다. 상위 입력 경로가 우선순위에 따라 정확히 하나를 선택하고, 선택된 기능은 원문과 선택 영역의 최종 결과를 한 번만 기록한다.

## 새 편집 기능 설계 절차

1. 사용자가 누른 한 동작과 기대 결과를 원문, 캐럿, 선택 영역으로 각각 정의한다.
2. 선택 영역 없음, 단일 줄 선택, 여러 줄 선택을 나누어 정의한다.
3. 렌더 모드 전용인지 원문 모드에도 필요한지 먼저 결정한다.
4. 조합 입력과 운영체제 단축키를 침범하지 않는 조건을 정한다.
5. LF와 CRLF에서 원문 위치 계산이 같은 의미를 갖는지 확인한다.
6. 기능 전체의 실행 취소와 다시 실행 경계를 정의한다.
7. 결과가 바뀌지 않는 경우 기본 입력 또는 무동작으로 안전하게 돌아가게 한다.
8. 상위 입력 우선순위에서 다른 기능과 충돌하지 않는 위치를 정한다.
9. 실제 키 입력으로 결과와 캐럿을 검증한다.

## 검증 체크리스트

편집 보조 기능을 추가하거나 바꾸면 최소한 다음을 확인한다.

- 캐럿이 줄 시작, 접두부 안, 본문 중간, 줄 끝에 있을 때 결과가 자연스러운가.
- 선택 영역이 한 줄과 여러 줄에 걸칠 때 원문과 선택 범위가 맞는가.
- 캐럿 뒤의 텍스트가 삭제되거나 순서가 바뀌지 않는가.
- LF와 CRLF 원문에서 같은 편집 의미를 유지하는가.
- 한글 조합 입력 도중 문자가 분리되거나 자동 기능이 끼어들지 않는가.
- 원문 모드의 기본 입력을 바꾸지 않는가.
- 기능 한 번이 실행 취소 한 번으로 돌아가고 다시 실행으로 같은 선택 영역까지 복원되는가.
- 결과가 없는 동작이 불필요한 실행 취소 기록이나 변경 표시를 만들지 않는가.
- 렌더 표시, 실제 입력, 캐럿, 선택 영역이 자동 줄바꿈 뒤에도 같은 위치를 가리키는가.
- 키 입력을 가로채는 기능은 값 직접 대입만으로 검증하지 않고 브라우저 자동화의 `press()`처럼 실제 키 이벤트를 보내는 방식으로 확인했는가.

## text-pad 적용 위치

- `src/routes/+page.svelte`: 렌더 모드 상위 키 입력, 캐럿과 선택 영역 변환, 편집 결과 기록.
- `src/lib/editor-command-pipeline.ts`: 편집 명령 식별자와 우선순위의 고유성을 검사하고 적용된 첫 명령에서 처리를 끝내는 공통 실행 경로.
- `src/lib/arrow-substitution.ts`: Space로 확정한 화살표 표기 인식, 원문 교체, 최종 캐럿 계산.
- `src/lib/markdown-heading-edit.ts`: Space로 확정한 Markdown 제목 표식 적용과 기존 단계 교체 계산.
- `src/lib/list-markers.ts`: 글머리 인식, 순번 증가, 깊이별 형식 선택.
- `src/lib/line-oriented-formats.ts`, `src/lib/markdown-settings.ts`: Markdown 제목 인식과 단계별 공통 표시 설정.
- `src/lib/editor-undo.ts`: 탭별 실행 취소와 다시 실행 기록.
- `docs/features/render-mode.md`: 렌더 표시와 파일 형식별 세부 계약.
- `docs/features/editor-undo.md`: 실행 취소 내부 계약.

렌더 모드의 자연스러운 편집 기능을 추가, 변경, 제거할 때는 구현과 같은 작업에서 이 문서와 `docs/features/natural-text-editing.en.md`를 함께 갱신해 두 언어가 현재 동작을 동일하게 설명하도록 한다.
