# 다국어 지원 계약

앱의 메뉴, 설정, 대화상자, 상태 표시, 문법 검사 결과와 사용자에게 보여 주는 오류 접두사는 번역표에서 관리한다. 사용자가 편집하는 원문, 파일 이름, 운영체제가 반환한 오류 상세 내용은 번역 대상으로 취급하지 않는다.

## 지원 언어

초기 지원 언어는 다음 10개다.

- 영어(`en`)
- 한국어(`ko`)
- 일본어(`ja`)
- 중국어 간체(`zh-CN`)
- 스페인어(`es`)
- 프랑스어(`fr`)
- 독일어(`de`)
- 브라질 포르투갈어(`pt-BR`)
- 러시아어(`ru`)
- 아랍어(`ar`)

로캘(locale)은 언어와 지역을 나타내는 코드다. 앱 시작 시 `navigator.languages`에 있는 시스템 언어를 순서대로 확인하고, 완전히 같은 로캘이나 같은 기본 언어를 지원하면 해당 번역을 사용한다. 예를 들어 `pt-PT`는 현재 지원하는 포르투갈어인 `pt-BR`로, `zh-TW`는 현재 지원하는 중국어인 `zh-CN`으로 연결한다. 지원 언어가 없으면 영어를 사용한다.

## 사용자 선택 우선순위

- `pref_language` 값이 `system`이면 시스템 언어를 따른다.
- 사용자가 설정창의 `일반 > 표시 언어`에서 특정 언어를 선택하면 해당 값이 시스템 언어보다 우선한다.
- 잘못되었거나 더는 지원하지 않는 저장값은 `system`으로 처리한다.
- 설정창과 메인 창은 `storage` 이벤트로 언어 변경을 즉시 공유한다.
- 시스템 기본값을 포함한 선택값은 `localStorage`에 저장해 다음 실행에도 유지한다.

## 번역표

- `src/lib/i18n/en.ts`는 모든 번역 키와 영어 대체 문구를 정의하는 기준표다.
- 나머지 언어는 `src/lib/i18n/<locale>.ts`에서 같은 키를 빠짐없이 제공한다.
- `src/lib/i18n/index.ts`는 지원 언어 목록, 시스템 언어 해석, 영어 대체, 치환 변수 적용과 오른쪽에서 왼쪽으로 읽는 언어 여부를 관리한다.
- `{fileName}`, `{version}` 같은 치환 변수 이름은 모든 언어에서 기준표와 같아야 한다.
- 새 사용자 노출 문구는 화면에 직접 쓰지 않고 먼저 영어 기준표와 모든 번역표에 키를 추가한다.
- 특정 언어에서 키를 찾지 못한 경우에도 화면이 비지 않도록 해당 키의 영어 문구를 사용한다.

## 문서 방향과 원문 보존

아랍어를 선택하면 앱 문서의 `lang`과 `dir` 속성을 각각 `ar`, `rtl`로 설정한다. `rtl`은 오른쪽에서 왼쪽으로 읽는 방향을 뜻한다. 다만 편집기와 CSV/TSV 셀의 사용자 원문은 `dir="auto"`로 두어, 각 입력 내용의 실제 문자 방향에 맞게 표시한다.

백엔드의 `FileCommandError.message`는 운영체제나 파일 시스템에서 받은 상세 내용만 반환한다. 프론트엔드는 현재 표시 언어의 읽기·저장 오류 문구를 앞에 붙인다. 따라서 백엔드에서 사용자 언어를 추측하거나 번역된 문장을 조합하지 않는다.

## 검증

- `npm run validate:i18n`: 10개 번역표의 키, 중복 키와 치환 변수 일치 여부를 검사한다.
- `npm run check`: 번역 키 타입과 Svelte 화면 연결을 검사한다.
- 보이는 UI 변경은 인앱 브라우저에서 시스템 기본값과 명시적 언어 선택을 확인한다.
- 앱 내용이 바뀌었으므로 마지막에 `npm run tauri build`로 Windows 실행 파일을 다시 만든다.
